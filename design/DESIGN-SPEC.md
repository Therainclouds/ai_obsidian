## 1 产品定义

### 1.1 一句话

> **一个把「对话」「文件」「知识点」自动连成网络的个人知识系统。**

用户只管往里丢东西和聊天，AI 负责理解、建立关联、把有价值的片段蒸馏成知识点。

### 1.2 与 Obsidian 的关键差异

| | Obsidian | 本系统 |
|---|---|---|
| 关联来源 | 用户手写 `[[双向链接]]` | **AI 自动建立**，用户只做确认 |
| 图谱含义 | 链接关系快照 | **演化轨迹**：信息如何一步步长成知识 |
| 知识结晶 | 靠用户自己整理 | **沉淀器自动蒸馏**成知识点 |
| 入口 | 编辑器为中心 | **对话为中心**，文件与图谱是它的两个侧面 |

这条差异决定了两件事：**进化图谱**必须展示"过程"而不是"结果列表"；**AI 必须无处不在**（对话页 + 全局悬浮球）。

### 1.3 模块地图

```
┌─ 全局层（常驻，不随页面切换）────────────────────┐
│  AI 悬浮球 ─ 点击 → AI 聊天小窗（读取当前页面上下文） │
└──────────────────────────────────────────────┘

┌─ 主应用 ────────────────────────────────────────┐
│  左侧常驻导航                                     │
│   [◈ 我的空间 ▾]  ← 知识空间切换器（原为分组标题）  │
│      ① 聊天  ② 文件管理  ③ 进化图谱  ④ 知识总结         │
│   系统      ⑤ 设置 & 我的                            │
│  内容区     当前模块                              │
└──────────────────────────────────────────────┘
```

**共 5 个页面 + 1 个全局层。** 命名与图标对应关系固定，不得随意增删一级入口。

> 「知识空间」在 v1.0 首次升格为**实体**（ADR-0006）：它是一套独立的内容边界，用户可建多个。侧栏那一行由分组标题改为**切换器**，同时承担"当前在哪"与"能换到哪"两件事。

### 1.4 三条核心用户路径

| 路径 | 起 | 中 | 止 |
|---|---|---|---|
| **蒸馏** | 聊天页抛出想法 | AI 抽取主题 → 关联已有文件 | 生成知识点（可在进化图谱看到轨迹） |
| **归档** | 文件管理导入素材 | AI 解析 → 建立边 | 图谱节点变亮，状态栏关联数 +N |
| **回看** | 知识总结看统计 | 发现高频知识点 | 跳回对应文件或图谱继续加工 |

## 2 设计原则

> 六条。每条都附「这意味着什么」——不是口号，是能落到代码的约束。

### 原则 1 · 克制优先
动效只在**承载信息**时出现，不做纯装饰。
**意味着**：氛围类特效（极光、粒子、点击火花、磁吸）一律不做。数字滚动、关联流光可以做——因为它们表达"数据在变化"。

### 原则 2 · 名词必须自带解释
任何一级入口，都必须有一句话说明它是干什么的。
**意味着**：侧栏导航项是「图标 + 名称 + 一句话」，如 `聊天 / 和 AI 对话，随手记录想法`。新增任何入口都按此标准，**不允许只放名词让用户猜**。

### 原则 3 · 三色闭环，零第四色
全站只有三种主体色：**墨（结构）· 靛（行动）· 陶（提示）**。所有细分颜色必须由这三色派生。
**意味着**：文件类型标签、图谱节点、链路节点、排名条形、状态点……全部映射到三色语义，不得引入第四种色相。

### 原则 4 · 颜色由算法派生，不手工挑色
底色、灰阶、点亮色都不手选，全部由**主色色相**按黄金律算出来。
**意味着**：换主色 = 换一个色相种子，整站重算，永远不会出现"冷主色坐在暖米黄上"的错配。

### 原则 5 · 一个 AI，两个入口
对话页与小窗背后是同一个 AI、同一份上下文。
**意味着**：小窗顶部必须明示「已读取当前页面：XX」，且随页面切换实时更新。

### 原则 6 · 无障碍是地基不是补丁
**意味着**：所有文字对比度 ≥ 4.5:1（大字号 ≥ 3:1）、键盘可达、尊重 `prefers-reduced-motion`。这三项在组件层就写死，不靠后期排查。

## 3 视觉系统

### 3.1 三色体系

| # | 名称 | 职责 | 面积占比 | Light | Dark |
|---|---|---|---|---|---|
| 01 | **墨 Ink** | 结构、文字、中性面 | ~90% | `#161821` | `#E8EAF0` |
| 02 | **靛 Indigo** | 主色：行动、选中、AI 本体、活跃关联 | ~6.5% | `#3B4CC0` | `#88A0F6` |
| 03 | **陶 Terracotta** | 点缀：需要注意的数据与产出 | ~3.5% | `#B35618` | `#E58C5B` |

> **定案记录**：v0.3 用的青 Jade `#146B57` 被否决；v0.4 给出「靛 / 钢 / 绛」三候选现场对比；**v1.0 定案靛 Indigo**。
> 靛与陶的 OKLCH 色相夹角为 **135.0°**，与黄金角 137.5° 仅差 2.5°，天然成立。

### 3.2 配色黄金律

整套色值由这三条规则算出（设置页「配色黄金律」区块把规则摊开给用户看，是产品的一部分）。

| 律 | 规则 | 参数 |
|---|---|---|
| **律 1** | 面积比 | 中性面 60% : 文字与结构 30% : 主色 6.5% + 点缀 3.5% |
| **律 2** | 中性面由主色派生 | 同色相 H，彩度 **C ≤ 0.014**，只动明度 L |
| **律 3** | 点缀色 = 主色 H **+ 137.5°**（黄金角） | 靛 `271.3°` → 陶 `48.8°` |

**推导出的色相定位**

| 角色 | 色相角 | 说明 |
|---|---|---|
| 主色（靛） | 271.3° | 种子 |
| 中性面（底 / 卡 / 线 / 灰阶） | 271.3° | 与主色同色相，彩度压到 0.014 以下 |
| 点缀（陶） | 48.8° | 主色 + 黄金角 |

> **为什么背景也要跟主色同相**：旧版浅色底 `#F4F3EF` 色相 95.1°，与靛相差 176°（几乎正对面），这才是"蓝色坐在米黄上"违和感的来源。不是米黄不好看，是**它和主色不是一个色族**。

**备选点缀（如选用）**：锁定 v0.4 的暖陶 `#B4551F` / `#E1904F`，覆盖 `--accent` 四值即可，其余不变。

> **陶色的使用纪律**：它只出现在"需要你注意"的地方。陶色一出现，就应该有含义。**装饰性地撒橙色是禁止的。**

#### 状态语义色（零第四色）

状态表达（成功 / 需要注意 / 中性）**不引入语义色**（红 / 绿 / 黄都不加），而是复用已有的三色语义：

| 状态 | 取色 | 落点举例 |
|---|---|---|
| **成功 / 运行中 / 已就绪** | **主色** | 连接成功、已配置、服务运行中、校验通过 |
| **需要注意 / 失败 / 待配置** | **点缀色** | 鉴权失败、待配置、未读角标、待确认项 |
| **未启用 / 中性 / 未测试** | 墨灰（`--ink-3` / `--surface-3`） | 已禁用的工具集、尚未测试、无数据 |

这条规则让"零第四色"能覆盖状态表达这一常见破口；陶色的既有语义（"需要注意的"）天然承接"失败与待办"。首次落地在设置页「AI 模型」面板（§5.4）。

### 3.5 主题机制

```html
<html data-theme="light">  <!-- 或 dark -->
```

- 首屏前在 `<head>` 内联脚本读取 `localStorage('ks-theme')`，无记录则跟随 `prefers-color-scheme`，**避免闪白**
- 切换入口：侧栏底部「切换黑夜 / 切换白天」按钮
- 过渡：`background-color / color / border-color` 各 `.3s`
- 暗色不是简单反色：底色用带靛调的 `#0D0F15`，主色提亮到 `#88A0F6`，点缀提亮到 `#E58C5B`

### 3.8 动效 Token

| 名称 | 值 | 用途 |
|---|---|---|
| `--ease` | `cubic-bezier(.22,1,.36,1)` | 通用（hover、颜色、展开） |
| `--ease-quart` | `cubic-bezier(.25,1,.5,1)` | 位移/进场（easeOutQuart） |
| 快 | `150–200ms` | hover、颜色变化 |
| 中 | `220–300ms` | 卡片浮起、按钮、面板 |
| 慢 | `400–500ms` | 页面进场、列表 stagger |
| 数据动画 | `900–1200ms` | 数字滚动、进度条生长 |

> **红线：缓动函数不出现弹性回弹（back / elastic）。** 弹性缓动是"AI 味"的主要来源之一。全站只使用 easeOut 系。

## 4 全局布局框架

### 4.1 应用骨架

```
┌──────────────┬────────────────────────────────────────────────┐
│ 侧栏 252px    │ 内容区（flex:1）                                 │
```

### 4.3 页面三段式

所有业务页面（文件管理 / 进化图谱 / 知识总结 / 设置）统一采用：

```html
<section class="page" id="page-xxx">
  <div class="p-head">   <!-- 标题 + 描述 + 操作，flex:none -->
  <div class="p-body">   <!-- flex:1, min-height:0, overflow:hidden -->
     <!-- 二段：可选左侧子栏 + 主区；或直接 .p-scroll 滚动 -->
```

**这条结构必须保持一致**，页面之间的切换才不会"跳"。聊天页是唯一例外（无 `.p-head`，用居中舞台 + 底部输入框）。

**四种 Hook 的语义（功能定义）**

| Hook | 英文 | 职责 | 默认 |

| 收集器 | Collector | 文件、网页、想法的统一入口，先存后理 | 开 |

| 关联器 | Linker | 把新信息与已有文件、知识点建立连接 | 开 |
| 沉淀器 | Distiller | 把对话与文件蒸馏为可复用的知识点 | 关 |

| hover 光束面板节点 | 描边加粗 |
| 点演化卡片 | **待定**：跳到对应文件 / 展开完整链路 |

#### 数据需求

| 元素 | 需要的数据 |
|---|---|
| Hook 开关 | 4 个模块的启用状态（需持久化） |
| 实时演化流 | 近期聚合计数：对话条数 / 文件个数 / 知识点个数 |

### 6.2 通用状态规范

> **第一原则：按「数据来源」分流，不按页面分流。**
> 给纯本地操作加加载态是**撒谎**——它会让用户以为"这也要联网"。本产品跑在**局域网内**，
> 本机到 agent 与知识空间零网络跳，唯一的网络依赖是**公网出口到云端模型**（ADR-0004）。
> 所以要区分的是"这一下要不要出网"，而不是"在线还是离线"。

| 数据来源 | 举例 | 需要的态 |
|---|---|---|
| **纯本地** | 切页面、切筛选、展开文件夹、切主题 | **无**（不加加载态） |
| **本地有耗时** | 打开大文件、全库搜索、重排图谱 | **只加载态**（骨架） |
| **云端往返** | 对话、蒸馏、关联计算、测试连接 | **完整三态** |

| 状态 | 粒度 | 规范 |
|---|---|---|
| **加载** | 三粒度 | 首屏骨架 / 局部骨架 / 内联等待；**禁止转圈**（唯一例外：AI 已在流式出字） |
| **空** | 四型 | 首次 / 中性 / 筛选后 / 搜索无果，见 §6.3.2 |
| **错误** | 五型 | 不可达 / 鉴权 / 额度 / 内容 / 本地，见 §6.3.3 |
| **成功反馈** | — | 轻提示（toast），**待设计** |

> **没有"离线"这一态**（2026-09-23 修订）。设备是局域网设备，不存在断网使用场景，本产品**不承诺离线操作**——不设离线模式、不做离线队列、不给全局横幅。云端调用的失败一律落进**错误 X1**，靠"失败不毁内容"兜住。

### 6.3 三态详细规格（v1.1 定案 · v1.2 修订：撤销离线降级）

#### 6.3.1 加载：三粒度，一个禁止

| 粒度 | 何时 | 形态 |
|---|---|---|
| **首屏骨架** | 页面首次进入、内容形状已知 | 骨架条块，**形状对齐真实内容**（行高、列宽一致） |
| **局部骨架** | 单块内容重取（换筛选后列表刷新） | 只替换那一块，工具栏保留 |
| **内联等待** | 形状未知（AI 正在生成） | 见下「AI 正在做」 |

- **禁止转圈。** 唯一例外：AI 已经在流式出字——那时有实质内容在动，转圈是多余的
- **禁止假进度条 / 百分比**：云端给不出真实进度，假进度比没有进度更糟

##### 「AI 正在做」是本产品的一等状态，不是普通加载

云端往返要几秒到十几秒，这段时间里有信息可给：

```
生成层 · 正在处理
● 读取 3 份素材              ← 已完成：主色实心点
● 整合与关联 · 找到 2 处连接   ← 进行中：主色点 + 脉冲环 + 主色文字
○ 写知识点 · 低粉爆款三要素    ← 未开始：墨灰点 + 墨灰字
```

- **三段正对应演化记录的 `trigger`**（收集器 / 关联器 / 沉淀器）→ **聊天里看到的，和进化图谱里记下的，是同一件事**
- 完成后**折叠成一行痕迹**留在对话里：`读取 3 份素材 · 找到 2 处连接 · 产出 1 个知识点` + 「在进化图谱里看 →」
- 视觉只给**主色 + 墨灰**，不引入新色
- 组件 `.think` / `.think-sum`

#### 6.3.2 空态：必须分四型

把四种空画成一样，会导致「筛选没结果」被写成「还没有内容」——**这是对用户撒谎**。

| 型 | 何时 | 标题示例 | 动作数 | 图形 |
|---|---|---|---|---|
| **E1 首次** | 从未有过数据，且刚创建了容器 | 「读书笔记」还是空的 | **最多 3 个并列入口** | 主色几何 + 起步卡 |
| **E2 中性** | 功能本身还没数据 | 还没有演化记录 | **1 个** | 墨灰几何 |
| **E3 筛选后** | 有数据，当前筛选无果 | 最近 7 天没有新文件 | **1 个**（查看全部） | 墨灰几何 |
| **E4 搜索无果** | 关键词无匹配 | 没找到「量子计算」 | **1 个**（清除搜索） | 墨灰几何 |

**不变量**

1. **空态留在内容区内**，不夺走工具栏 / 筛选条——否则用户不知道当前处在什么条件下（E3 / E4 的命门）
2. **E3 / E4 的标题绝不能出现「还没有内容」**：东西还在，只是没露出来。文案要主动说清（"你的 128 个文件都还在"）
3. **只有 E1 允许并列动作**：那时用户的任务是"知道这里能装什么"；E2–E4 的任务是"从当前处境出去"，给多了是选择困难
4. **不用插画**（插画必然引入第四色），一律几何描边图形
5. E1 的入口必须是**动词短语**（导入文件 / 新建笔记 / 网页剪藏），不是名词
6. E3 / E4 的筛选条必须**真的停在**对应项上——空态说"最近 7 天"，筛选条就不能还高亮"全部"

> **关键案例：新建知识空间后的空**，是全套三态里最重的一处——文件树、图谱、知识点三块同时为空。
> 解法不是"三个空白框"，而是分块对待：树那一栏给一句轻提示；主区给 **E1 起步引导**；
> 图谱页**保留四个 Hook 开关与通道示意**（通道不是内容，用户要看到它随时可以通），只空掉轨迹区。
> 反例纠正：空空间里演化流的示意节点不能还写着"对话 · 12 条"——**"空"与"12 条"自相矛盾**，必须跟着归零并灰化。

#### 6.3.3 错误：分五型，一律陶色

| 型 | 触发 | 可重试 | 出口 |
|---|---|---|---|
| **X1 模型服务不可达** | 超时 / 5xx / 公网出口不通 | ✅ | 重试 + **草稿不丢**（§6.3.4） |
| **X2 鉴权失败** | 401 / 403 | ❌ | **去设置页修密钥** |
| **X3 额度耗尽** | 429 / quota | ❌（等待） | 换模型 / 稍后再试 |
| **X4 内容错误** | AI 输出不合格 / 解析失败 | ✅ | 重试 + 可展开的原因 |
| **X5 本地错误** | 磁盘满 / 权限 | ❌ | 展示具体路径 |

**不变量**

1. **失败不毁内容（stale-while-error）**：刷新失败时保留旧数据，只在顶部挂一条；**绝不把已渲染的内容清空**
2. **局部失败 ≠ 整页失败**：图谱坐标算不出来时，模块条与列表照常，只降级那一块（`.degrade`）
3. **错误必须给出口**，不给出口的错误条是死胡同
4. **文案说人话**：`云端连不上` 而不是 `ECONNREFUSED`；技术细节（trace / 错误码）折叠在等宽小字里
5. 语义色一律**陶色**（D19）——不引入红

#### 6.3.4 失败不毁内容：X1 的三条落地

> **本节原先叫「断网降级」，2026-09-23 整节撤销。** 设备是局域网设备，不存在断网使用场景，本产品不承诺离线操作。

撤销之后，剩下的只有它真正有价值的内核——**一次云端调用失败时，用户不该付出任何代价**：

| 不变量 | 落地 |
|---|---|
| **用户写的东西不丢** | 发送失败时消息留在对话里、输入框里的草稿不清空；**不弹遮罩、不锁输入框** |
| **已经渲染的东西不清空** | 失败只在对应位置挂一条错误条，**绝不把已有内容换成白屏**（同 §6.3.3 第 1 条） |
| **失败必须可继续** | 错误条内联「重试」；若是配置问题（缺 Key / Base URL 错）再给「去设置页」 |

**明确不做的事**（防止开发照抄旧版规格）：

- ❌ 全局离线横幅、`body.is-offline` 这类全局模式开关
- ❌ 离线队列、`已排队 n 项`、队列徽标
- ❌ "联网后自动继续"的自动补跑叙事——用户没发送成功，就不该有个后台等着替他发

> **顺带澄清一处容易被误读的**：浏览文件树、搜索、看历史演化记录**本来就是纯本地的能力**，
> 不是"降级之后还剩什么"。收集器与解析器零 token（ADR-0002），它们不依赖任何网络，也不需要被特殊照顾。

**X1 的文案范式**（原型 `.msg-err` 已落地）：

```
没能连上模型服务 · 这次调用超时，已自动重试 2 次。你那条消息没有丢，重试即可继续。
gateway · upstream_timeout · attempt 3/3 · 12.4s              [重试]  [去设置页查配置]
```

- 标题说清**是哪一环**断了（模型服务），**不说"网络错误"**——用户在局域网里，说"网络"会把他引去查路由器
- 正文**先给结论再给保证**：`已自动重试 2 次`是结论，`消息没有丢`是保证
- 技术细节折叠进等宽小字，**attempt 计数要有**：它解释了"为什么是现在才报错"
- 出口只给两个：**重试** / **去设置页查配置**（后者通往 X2 的修法）

## 7 动效规范

### 7.1 三层分工

| 层 | 承担者 | 占比 | 内容 |
|---|---|---|---|
| **L1 系统层** | 原生 CSS | ~70% | 页面切换、列表错峰进场、hover、焦点环、主题过渡 |
| **L2 交互层** | 关键动效（Magic UI 思路） | ~20% | 数字滚动、关联流光、卡片光斑、边框光、按钮扫光、打字机 |
| **L3 氛围层** | react-bits 思路 | ~10% | **本版全部关闭**，仅预留首页 AI 球 |

**结论：动效锁定「克制档」。** 保留 L1 + L2，L3 氛围类一律不做。

### 7.3 禁用清单（红线）

**永远不做：**

| 禁用 | 原因 |
|---|---|
| 极光 / 渐变流动背景 | 常驻 WebGL，长驻工具下持续占用 GPU |
| 轨道粒子 / 星空 | 同上，且与"工具"气质冲突 |
| 点击火花 / 磁吸跟随 | 高频重复，第一次有趣、第十次烦人 |
| Meteors / Particles / Shiny Text / 全息边框 | 典型"AI 生成感"，属于 AI 产品标配而本产品刻意避开 |
| 弹性回弹缓动（back / elastic） | "AI 味"的重要来源 |
| 自动播放的装饰性视频 / GIF | 分散注意力、增加体积 |

### 7.4 性能约束

- 常驻动画**不超过 3 个**（当前：球呼吸、状态点脉冲、流光 1 处）
- 流光使用 SMIL，避免 JS 逐帧
- 数据动画统一 `requestAnimationFrame` + easeOutQuart，不用第三方库
- 离屏页面内的动画应随页面切换停止（当前由 CSS 动画自然处理，React 化后需注意）

## 9 开发交接

### 9.1 技术栈（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **React + Vite + TypeScript** | 组件化，且 shadcn 生态互通 |
| 样式 | **Tailwind CSS** | token 可一对一映射，与 shadcn 同源 |
| 组件基座 | **shadcn/ui** | 源码进仓库，能长成自己的设计系统 |
| 动效（L2） | **Magic UI** | 与 shadcn 同生态，Motion + Tailwind 统一引擎 |
| 动效（L3） | **react-bits**（按需，当前不引入） | 保留为"特效补给站"，仅在确有必要时用 |
| 状态 | **TanStack Query**（服务端状态）+ **Zustand**（UI 状态：主题 / 当前空间 / 小窗开合） | 宿主是唯一数据源，走 **IPC**；本地 UI 状态不该进 query cache。**原"待后端形态确定"至此解除**（ADR-0008）|
| **渲染器形态** | **Electron 应用**（`nodeIntegration: false` · `contextIsolation: true`） | 它不再是"一个网页"——没有地址栏、有自己的窗口、能开机自启。**桌面壳的选择与判据见 ADR-0009** |
| **本地宿主** | **Electron 主进程**（Node，与知识空间同机，见 §9.1.3） | 承载 Harness、ACP 客户端与本地索引；宿主做不到的事全归它。见 ADR-0008 / ADR-0009 |
| **运行时** | **Hermes Agent**（自托管，ACP 接入） | 生成层的**工具循环**执行者：读素材、调工具、写字、落盘。**由本地宿主拉起为子进程**。见 §9.6 |
| 决策层 | **Jev 类决策模型**（云端调用） | 只做判断，返回类型化答案 + 置信度；见 §9.1.2 |
| 生成层 | **云端 LLM**（由运行时调用） | 写知识点正文。**Jev 不产出任何文字**，两者不可互相替代 |

> **不引入**：任何自带整套主题的 UI 框架（会与我们的三色体系冲突）。

#### 9.1.1 部署目标与算力边界（这一节决定架构）

**客户端部署在 Rockchip RK3528 上**：4×Cortex-A53 @2.0GHz、L1 256KB + L2 512KB、Mali-450 MP2（≈23.8 GFLOPS FP32）、内存上限 4GB（DDR3/LPDDR3/DDR4/LPDDR4）、TDP 5W、Geekbench 5 单核 ≈140。

| 硬件约束 | 对设计的后果 |
|---|---|
| **无可用 NPU、内存上限 4GB** | 本地跑不了任何有意义的模型——连 3B 量化都没余量，9B 级（Open-Jev 的基座）完全不可能。**AI 能力必须全部走云端** |
| **GPU 仅 ≈23.8 GFLOPS** | **禁用常驻 Canvas / WebGL**。"动效克制档"（D7）不只是审美取舍，也是硬件决定 |
| **CPU 单核 ≈140** | **重计算留在本地，但必须给骨架**：全库搜索、图谱布局与聚合属于**本地有耗时**（§6.2 三档），受得起慢、受不起出网。只有**需要模型的 embedding 计算**才出网。〔v1.4 修订：原文"重计算全部下沉云端：…全文检索…图谱聚合"与 §6.2 把「全库搜索 / 重排图谱」归为本地有耗时直接冲突〕|
| **5W 功耗 + 站点在局域网内** | 每个 AI 动作仍是一次**公网**往返（唯一出网路径）→ **三态是主路径而非异常**（§6.3）。注意：网络本身不是弱点，弱点是我们替不了云端模型的可用性 |

**架构形态**〔v1.4 修订，定案见 ADR-0008〕：设备本地 = **渲染器 + 本地宿主 + agent 运行时**（三者同机，ADR-0004）；云端 = **决策层 + 生成层**——**只有算力在云端，编排不在**。宿主是知识空间唯一的写入者。
> 原文为「客户端 = 瘦渲染器；云端 = 编排 Harness + 决策层 + 生成层 + 索引」，是 v1.0（D14 时代）的旧句。ADR-0002 / ADR-0004 之后编排与 agent 运行时刻意钉回了设备本地：Harness 若在云端，就无法以本地路径为 cwd、无法写设备上的演化记录、无法读 `~/.hermes/config.yaml`——ADR-0004 的整条论证会随之瓦解。

#### 9.1.2 决策层的接入纪律

决策层走云端（理由见 §9.1.1），但**代码里不许出现"Jev"这个专名**——必须抽象成可替换接口：

```ts
decide(questions: Question[], state: State) -> {
  answers: { [name]: { choice?|noul?|score?, probabilities, confidence } },
  decidedBy: string,   // 哪个实现产出的，随结果一起落库
}
```

两条硬约束：

1. **`confidence` 必须和 `decidedBy` 一起存**。没校准过的概率不是置信度——如果哪天换成普通 LLM 打分，那个 `0.82` 的含义完全不同，不留来源就永远说不清。而 `confidence` 只由**关联器**和**沉淀器**产出；**收集器**和**解析器**不判断，没有置信度。
2. **不能用 `confidence` 单独 gate 自动动作**。素材是用户投进来的不可信内容——有公开案例：往上下文注入一个伪造的"工具输出"字段，就把一个拦截决策从 `0.76 / 置信度 0.64` 打到 `0.48 / 0.22`。凡是要**写入图谱**这类有后果的动作，阈值之外必须另有一道确定性检查。

> **地域前提**：Jev 官方服务目前**未向中国大陆开放**，原版权重也未开源（只有云端 API）。若走官方接口需要先解决可达性；替代路径是**自建云端跑开源复现**（Open-Jev：Qwen3.5-9B + LoRA + 决策头，适配器 Apache-2.0、代码 MIT），本质仍是云端接入、客户端零负担，且不受地域限制。**决策层抽象成接口后，这三条路可以随时互换。**

#### 9.1.3 进程拓扑（v1.4 新增 · **v1.5 改为桌面应用** · ADR-0008 / ADR-0009）

§9.1 原表只列了前端，漏掉了承载 Harness 的那一层。本节补齐——**这就是 M0 要立起来的东西**。

```
┌─ 设备本地（RK3528）───────────────────────────────────────────────┐
│                                                                   │
│  Electron 应用                                                     │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │ 渲染进程 ── 渲染器（无文件系统、无进程）                       │  │
│  │   nodeIntegration: false · contextIsolation: true            │  │
│  │     │                                                        │  │
│  │     │  IPC（唯一通道 · preload 白名单 · 不再有端口）           │  │
│  │     ▼                                                        │  │
│  │ 主进程 ── = 本地宿主（Node）                                  │  │
│  │   ├─ Harness          四个 Hook 的确定性编排                   │  │
│  │   ├─ ACP 客户端        stdio JSON-RPC                        │  │
│  │   ├─ 本地索引          全库搜索是本地能力（§6.2）               │  │
│  │   └─ 知识空间读写      ★ 设备上唯一的写入者                     │  │
│  └──────────────────────┬──────────────────────────────────────┘  │
│                         │ stdio（spawn 子进程）                    │
│                         ▼                                         │
│  agent 运行时 ── Hermes（`hermes acp`）                            │
│     持模型配置 · 持会话 · 做工具循环                                 │
└───────────────────────┬───────────────────────────────────────────┘
                        │ 公网 HTTPS（唯一出网路径）
                        ▼
               云端：决策层 + 生成层
```

**四条边界**

1. 渲染器**不直连** agent 运行时——通道只有一条，就是 preload 暴露给它的那组白名单方法
2. 宿主（主进程）是**唯一**持有知识空间写权限的进程；agent 只是它拉起的子进程 → ADR-0005 修订的"演化记录由 Harness 写"由此从**约定**升级为**能力**
3. 宿主的 cwd 解析只允许发生在 `agent/spaces.ts` 一处（ADR-0006）
4. agent 运行时是宿主的**子进程**，不是并列服务——宿主退出它就该退出，避免"一个 home 两个 agent"（ADR-0002 §5）

**为什么是 Electron，而不是 Tauri**（v1.5 改判 · 详见 ADR-0009）：

- **Electron**：主进程天然是 Node，`agent/` 那 510 行一行不用重写；官方发布 **linux-arm64 预构建**，不需要交叉编译；只加 `electron` 一个依赖。**而且它删掉的东西比加的多**——不再需要 localhost HTTP（端口 / 静态托管 / CORS / `EventSource`）
- **Tauri**：运行时**可能**最省（Linux ARM64 走 WebKitGTK，通常轻于 Chromium），磁盘占用也小得多。否决理由是**它解决不了本案要解决的事**：宿主要么翻译成 Rust（重写 `acp-client` / `spaces` / `model-config`，丢掉 Node 侧现成的 ACP stdio 支持），要么打 Node sidecar——**那仍然是两个进程，而这次的目的正是不再是两个东西**。附带成本是目标机需装 Rust 工具链 + webkit2gtk 开发包，且运行期绑定发行版的 WebKitGTK 版本

> **仍在，但换成了"待实测"**：ADR-0008 说"Electron 常驻 150MB+ 撞 4GB 预算"——这句**只对了一半**。浏览器也是 Chromium、也是 150MB+，同一把尺子量两边，Electron（主进程即宿主）反而少一个 Node 进程，且在专用设备上**不存在那个"本来就要开的浏览器"**。但这仍然是数量级判断，不是实测：**换壳的收益是产品形态与少一层通道，内存是平手到略省，必须实测才知道**。

> **M0 验收项（v1.5 第三次改写）**：实测 **Electron 应用（主进程 + 渲染进程，含辅助进程）＋ Hermes** 的总常驻与冷启动。**ADR-0004 §6 那句"必须在浏览器前端同时开启的场景下测"作废**——渲染器本来就在被测进程树里，所以口径反而更严（以前那句只是口头约束）。

#### 组件基座在 CSS 里，不在 `components/ui/`（2026-09-28 定）

原先打算照 shadcn 那套在 `src/components/ui/` 建一层 React 组件（Button / Chip / Input / Switch / Segmented / Panel）。**这条路已废弃，那批组件已删除。** 原因是一次实际事故：

把它们用 Tailwind 工具类「翻译」原型，等于把原型里几百个数值人工折算一遍——**必然走形**。事实是确实走形了：侧栏没有选中态竖条、图标是文本字形、聊天页变成占位卡片，用户一眼就看出"跟我们之前搭的 demo 完全是两回事"。

**现行办法**：原型的 CSS **逐值原样移植**成组件类（`src/styles/globals.css` · `src/styles/settings.css`），JSX 直接用同一套类名——`.nav-item` · `.p-head` · `.ghost-btn` · `.primary-btn` · `.chip` · `.role-card` · `.composer-box` …… Tailwind 工具类只用于一次性的局部排布。

**为什么不再建 `components/ui/`**：原型本身就是**可点击的组件库**——所有组件、所有状态、所有尺寸都在里面，而且是视觉唯一基准。再维护一层 React 包装，就多出**第二套并行样式系统**，而"两套东西慢慢不同步"正是上面那次事故的成因。少一套就少一处漂移源。

**代价（明说）**：组件没有 props 层的类型约束，靠类名约定；跨页复用时要自己保证类名一致。用一条纪律换掉一层抽象，这笔账在"视觉必须逐值对齐原型"的项目里划得来。

### 9.6 Agent 接入层

> 完整决策与论证见 `docs/adr/0002-hermes-orchestration-split.md`（编排分治）、`docs/adr/0003-model-config-source-of-truth.md`（模型配置）、`docs/adr/0004-agent-runtime-runs-on-device.md`（部署形态）、`docs/adr/0005-skill-sink-boundary.md`（技能下沉边界 + 用户技能修订）、`docs/adr/0006-knowledge-space-boundary.md`（知识空间边界）、`docs/adr/0007-what-counts-as-an-entity.md`（内容实体边界）。

**编排形态：前后台分治**

| 场景 | 编排者 | 形态 |
|---|---|---|
| 聊天（用户在场的开放对话） | **Hermes 自主驱动** | ACP 会话，多轮，agent 自己决定调哪些工具 |
| 四个 Hook（收集 / 解析 / 关联 / 蒸馏） | **我们的 Harness** | 确定性代码串联；Hermes 只在"该写字"那一步被叫进来 |

原则：**不给不确定的东西以编排权**。收集器入库本来就不该由 LLM 决定；蒸馏写字才需要 agent。副产品是收集器与解析器零 token——在 4GB / 5W 的设备上是实打实的收益。

**接入协议**：`hermes acp`（ACP，JSON-RPC over stdio）。Home 在 `~/.hermes/`：`config.yaml`（非密钥设置）、`.env`（密钥）、`auth.json`（OAuth）、`skills/`、`memories/`、`state.db`。

| # | 事实 | 说明 |
|---|---|---|
| 1 | **帧格式 = 换行分隔的裸 JSON** | **不是** LSP 的 `Content-Length` 头。证据：`acp/connection.py` 的 `readline()` + `json.loads(line)`。第一版按 LSP 帧写，适配器直接报 `Error parsing JSON-RPC message` |
| 2 | **必须等适配器就绪后再发** | 早于读循环写入的消息会被启动阶段吞掉 —— 表现极具迷惑性：`ACP client connected` 已打印，`initialize` 却永远不回。做法：监听 stderr 出现那句日志后再发包（+500ms） |

`initialize` 的返回（原样摘录）：

```json
{
  "protocolVersion": 1,
  "agentInfo": { "name": "hermes-agent", "version": "0.21.5" },
  "agentCapabilities": {
    "loadSession": true,
    "promptCapabilities": { "image": true },
    "sessionCapabilities": { "fork": {}, "list": {}, "resume": {} }
  },
  "authMethods": [
    { "id": "hermes-setup", "type": "terminal", "args": ["--setup"],
      "name": "Configure Hermes provider" }
  ]
}
```

`session/new` 的形状：无 provider 时返回 `-32603`，且 **`error.data.details` 是字符串**（内含 "Run `hermes model` to pick one"）—— 与 multica 的测试 fixture 一致，可据此判 X2 鉴权型错误。

**时延**：进程启动 → `initialize` 返回约 **3 秒**；`session/new` → 会话可用约 **15 秒**（含 MCP 发现与 agent 构建）。
→ 直接印证 §9.4「冷启动耗时进入体验指标」，也说明 §6.3.1 的「AI 正在做」三段回显是**必需**而不是修饰。

**环境开关**：`HERMES_ACP_SKIP_CONFIGURED_MCP=1` 可跳过启动期 MCP 发现（官方注释称省 2–5 秒）。

> ⚠️ **要带进部署的一条**：Hermes 自带的 SQLite 3.49.1 命中 WAL-reset 损坏 bug，它自动降级为 `journal_mode=DELETE` 并打警告。设备上那份是 v0.15.2（更旧），**装好第一件事是跑 `hermes doctor`**。

**进程拓扑**（v1.4 定案 ADR-0008 · **v1.5 改壳** ADR-0009）：**渲染进程 → IPC → Electron 主进程（= 本地宿主）→ agent 运行时（宿主的子进程）**。宿主承载 Harness、持有 ACP 的 stdio、建本地索引，且是**设备上唯一持有知识空间写权限的进程**。完整拓扑图见 §9.1.3。由此，ADR-0005 修订说的"演化记录由 Harness 写"不再只是约定——agent 连写权限都没有。

**工具集白名单（安全硬约束，不开放给用户改）**

| toolset | 状态 | 理由 |
|---|---|---|
| `file` · read / search | **开** | 蒸馏要读素材与知识点 |
| `file` · write / patch **按作用域切** | **知识空间根 关 · `~/.hermes/` 开** | ADR-0005 修订：**agent 可以改自己的脑子，不能改用户的资料** |
| `skills` / `session_search`（只读）/ `vision`（按需） | **开** | 组织写字步骤、回溯历史对话、解析图片 |
| **`terminal`** | **关** | 素材是不可信输入，允许执行任意命令 = 把执行权交出去 |
| **`execute_code`** | **关** | 同上 |
| `web` / `browser` | 关 | 素材由用户投进来，不由 agent 自行上网取料 |
| `memory` | 关 | 与知识点语义冲突，见下第 2 条 |
| `todo` / `delegate_task` | 关 | 单用户单库无收益；后者还放大不可控面 |

> 反例留档：`multica` 在调用 Hermes 时写死 `HERMES_YOLO_MODE=1`（全自动批准所有工具调用），并为此搭了一套 per-task `HERMES_HOME` overlay。那是为多租户设计的，与我们的威胁模型冲突——**不照抄**。

**四条边界**

1. **cwd 恒为「当前知识空间」的根**（ADR-0006 修订），没有越权路径；此值不暴露到设置页——那是边界，不是偏好。改 cwd 只允许发生在 `agent/spaces.ts` 一处
2. **运行记忆 ≠ 知识点**：`~/.hermes/memories/` 是 agent 为**自己**写的私有草稿（`MEMORY.md` 约 2200 字符 + `USER.md` 约 1375 字符，**会话开始时冻结快照**，用户看不见）；知识点是用户的资产，要能打开、要进图谱。前者一律叫**运行记忆**
3. **会话不共用**：不读 `state.db`（那是 agent 的会话账，表结构属于其内部实现）。对话素材作为**领域实体自己存**，打通方式是蒸馏时把对话内容显式喂给 agent
4. **一个 home 一个 agent**：Hermes 的硬约束——两个进程指向同一 home 会互相污染运行记忆 → 调用**串行化**

**模型配置**：单一事实来源是 Hermes 的原生配置（`config.yaml` + `.env` + `auth.json`）；设置页做**受限读写**，优先走 Hermes CLI（`hermes config set`），fallback 才直接改文件且必须保留注释。写入路径优先级与面板规格见 §5.4。

**「重载 agent」是唯一的生效动作**：到 ADR-0006 为止，有三处改动需要重载才生效——**模型配置**（ADR-0003 §3）、**技能变更**（ADR-0005 §3）、**知识空间切换**（ADR-0006）。三者**合并为一个动作**，设置页只出现一次（约 3 秒）。分开暴露会让用户以为"改了三样要重启三回"。

**部署形态：与知识空间同机，跑在设备本地**（ADR-0004）

Hermes 是"进程 + 云端模型"的组合，进程本身不做推理。定案：**进程跑在设备本地**，不作为可配置项，不提供"云端模式"——两种形态会分裂 cwd 的安全边界语义、上传策略与降级设计，收益只是一个开关。

官方最低配置是 **1 vCPU / 512MB 内存 / 2GB 磁盘**（支持 ARM64），我们不做本地推理（D14），正落在低配场景。由此产生的约束：

1. **内存是硬预算** —— 工具集白名单同时是内存策略（`browser` / `web` / `terminal` 是常驻内存与子进程的主要来源）
2. **所有推理在云端 → 「加载 / 空 / 错误」三态是常态而非异常**：每次解析 / 关联 / 蒸馏都是一次**公网**往返（局域网内本机到 agent 零跳，出网才是变量）→ 失败要落在错误态上，而不是让页面转到超时。**不承诺离线操作**（旧版"断网降级"已撤销，见 §6.3.4）
3. **冷启动耗时进入体验指标** → 常驻 gateway 是体验要求，不是架构偏好（ADR-0002 §5）
4. **设备是单点** → 数据格式不得引入"只有我们的服务才解得开"的形式

> **M0 验收项**（v1.4 单进程→双进程，ADR-0008 §5 · **v1.5 第三次改写**，ADR-0009 §1）：在 4GB / ARM64 上实测 **Electron 应用（主进程 + 渲染进程 + 辅助进程）＋ Hermes** 的总常驻内存与冷启动耗时。**原"浏览器前端同时开启"那句作废**——渲染器本来就在被测进程树里。

**技能：双命名空间**（ADR-0005 + 2026-09-23 修订）

Hermes 的 skill（`SKILL.md` + frontmatter，三级渐进披露）在官方安全模型里是**高信任载体**——"等价于本地主机代码，可读环境变量、可执行任意命令"。因此往技能里放东西不是"写文档"，是**授权能力**。

**产品侧**定案：技能只承载质量标准与输出契约；"什么时候写、按什么顺序写"留在 Harness。四个 Hook 里实际只有一个需要产品技能：

| Hook | 谁做判断 | 需要 agent | 产品技能 |
|---|---|---|---|
| 收集器 | 无人判断 | 否 | 无 |
| 解析器 | 无人判断（类型是文件事实：MIME / 扩展名 / 文件头） | 否 | 无 |
| 关联器 | 决策层（Jev 类） | 否 | 无 |
| 沉淀器 | 决策层（够不够蒸）+ agent（写正文） | **是** | **1 个**：蒸馏的写作规范 |

**用户侧放开**：用户或 agent 自己在 `~/.hermes/skills/` 创建的技能**数量不限**，产品不 review、不点名、不保证。两个命名空间并列——**不得只数其中一类，也不得在界面上合并成一个列表**：

| | 产品技能 | 用户技能 |
|---|---|---|
| 谁写 | 我们，随版本发布 | 用户或 agent 自己 |
| 住哪 | `agent/skills/`（挂载） | `~/.hermes/skills/` |
| 谁触发 | 产品代码**点名** | agent 自主（含闲聊中） |
| 产品是否 review | 是：进 git、可回滚、可 audit | **否** |
| 界面上 | 只读 | 可见 / 可启停 / 可编辑 |

**六条规则全部只约束产品技能**：

1. **技能正文里不出现时序词**（"先…再…然后…"），出现即越界
2. **触发权归 Harness**：技能由 Harness 点名调用；`description` 不得写成会被 agent 在闲聊里自主触发的口吻
3. **不写知识空间文件**：知识点文件、来源关系、演化记录一律由 Harness 写。这条现在由工具集的**作用域切分**保障，不再只是一句约定
4. **技能文件住在我们仓库**（`agent/skills/`），经 Hermes 的外部技能目录挂载；`~/.hermes/` 不进 git、不是产品的一部分
5. **技能里不放脚本、不声明 `env_passthrough`**，纯 markdown 提示词
6. ~~**不启用 agent 的"自我生成技能"**（官方特性，会把未经 review 的行为定义写进高信任目录）~~ —— **已撤销**（ADR-0005 修订）：那正是用户要的能力。取而代之的是一条**边界**，不是禁令：**agent 可以改自己的脑子，不能改用户的资料**

由此关闭一条原本的开放问题：**演化记录由 Harness 写，不由 agent 写**——即使 agent 自主触发了技能，它也没有写权限。修订后这条由**能力**保障而非约定：`file` 的 write / patch 对知识空间根关闭（见上工具集表）。

**用户技能的边界靠能力维持，不靠自觉**：

| 环节 | 谁定 | 用户技能能改吗 |
|---|---|---|
| 要不要入库（相关不相关、够不够蒸） | 决策层 | 不能——独立服务，够不着 |
| 什么时候写、按什么顺序写 | Harness | 不能——编排在产品代码里 |
| 怎么写（质量标准、输出契约） | 生成层读技能 | **能** ← 用户技能的全部作用域 |

产品的三项义务（已落进 §5.4 技能面板）：**① 标记来源**——两个分区 + "系统不保证"；**② 拦截脚本面**——带可执行脚本或声明 `env_passthrough` 的技能拒绝加载并说明原因；**③ 告知 token 成本**——用户技能可能被闲聊触发，消耗云端推理的费用

**知识空间与 agent 实例是两回事**（ADR-0006）

| | 切分依据 | 默认 |
|---|---|---|
| **知识空间** | 内容归属：文件树 / 知识点 / 关联 / 演化记录 | 用户可建多个 |
| **profile** | agent 的身份：运行记忆 / 技能 / config | **只有一个**（`default`），全部空间共用 |

**为什么默认不绑定**：一对一会让**每次切换知识空间都要冷启动**——直接违反 ADR-0004 §3 的"常驻 gateway 是体验要求"——并让模型配置分裂成 N 份（用户在空间 A 填的密钥在空间 B 不存在，看起来像"设置坏了"）。高级设置里允许绑定，**默认关闭**，开启前必须明示三条代价：内存占用 / 切换时冷启动 / 模型配置需另设。

| D28 | **内容实体的判定标准** | 三个含混项各自悬着 → **统一为"它有没有走一次演化"**：走了的是实体，没走的是视图——不进图谱、不产生来源关系、不计入统计（ADR-0007）| 这条是 ADR-0001 不变量的逆读（产出为空的是日志不是演化）。没有它，`kind` 该有几个值、"来源"会不会分裂、图谱收录什么，全都无解 |
| D29 | **对话的定性** | 它是不是一种素材、进不进文件树 → **是素材的子类（对话素材）**：没有文件夹归属、不进文件树，只作为**来源**出现在知识点里（ADR-0007）| 若让它成为第三类实体，「来源」就分裂成两个词（`← 素材` 与 `← 对话`），此后每加一种输入都要再扩一次。归进素材后，来源关系的箭头永远只有一个方向 |
| D30 | **周期回顾的定性** | 与知识点是否同一回事 → **不是**：它是把已有知识点按时间重排的**视图**，不进图谱、不产生来源关系（ADR-0007）| 若它算知识点，来源关系会出现「知识点 ← 知识点」，冲击已定案的方向；且它的价值是**帮我看**而不是**帮我记**，沉成实体等于让图谱从"知识怎么长出来的"变成"内容与日志的混合物" |
| D31 | **「全部」的计数范围** | 只数素材 or 素材 + 知识点 → **只数文件素材**（= 各文件夹之和）| D12 已定胶囊是视图切换器；既然「知识点」是独立胶囊，「全部」再含它就是同一个视图出现两次，且数字会对不上（筛选条写 184、树里只有 128 个文件）|
| D32 | **宿主形态** *(渲染器那半已被 D33 取代)* | 技术栈只列前端、缺一整层 → **本地 Node 宿主 + 浏览器**：设备本地 = 渲染器 + 宿主 + agent 运行时；云端只留决策层与生成层（ADR-0008）| 浏览器没有进程与文件系统，`acp-client` / `spaces` / `model-config` 一件也做不到——§9.3 却把它们放在 `src/` 下。宿主若真放云端（§9.1.1 旧句），ADR-0004 的整条论证（素材与知识空间不离开设备）会随之瓦解。**"Electron 撞 4GB 预算"这半条判错了，见 D33** |
| D33 | **渲染器形态** | "一个网页"还是"一个应用" → **一个应用**：渲染器 = Electron，**主进程即本地宿主**，通道由 localhost HTTP 换成 **IPC**；Tauri 否决（它解决不了本案的问题：宿主要么重写 Rust、要么打 Node sidecar，**那仍是两个进程**）（ADR-0009）| ① 目标机是**专用设备**，"本来就要开浏览器"这个前提不成立；② ADR-0008 否决 Electron 的理由（150MB+）**对浏览器同样成立**，同一把尺子量两边，Electron 反而少一个 Node 进程；③ 它用"ADR-0004 §6 要求浏览器同时开启"证明"渲染器必须是浏览器"，是**循环论证**——那是测量场景不是形态规定。**且它删掉的比加的多**：不再需要端口、静态托管、CORS、`EventSource` |
