## 上午：删掉并行样式系统（`ef64b19`）

删了 `src/components/ui/*`（Button / Chip / Input / Switch / Segmented / Panel）与展示它们的 `#kit` 组件库页。

**起因**：用户看过 M0–M2 的成果后说「跟我们之前搭的 demo 完全是两回事」。核下去，根因是我把原型的 Tailwind 工具类**手译**成 React 组件——等于把几百个数值人工折算一遍。走形的证据：侧栏没有选中态竖条、图标是文本字形、聊天页成了占位卡片。

**定案**：组件基座回到 CSS。原型的 CSS **逐值原样移植**成组件类（`globals.css` / `settings.css` / 每页一个），JSX 直接用同一套类名。**理由**：原型本身就是可点击的组件库，所有组件、所有状态都在里面，而且是视觉唯一基准；再包一层 React 就多出第二套并行样式系统，而"两套东西慢慢不同步"正是这次事故的成因。**少一套就少一处漂移源。** 代价明说：没有 props 层类型约束。

原因写进 DESIGN-SPEC §9.3 并标注「不要再建 `components/ui/`」。

## 傍晚：ADR-0009 —— 渲染器是桌面应用

**用户提出「这个系统我认为还是需要前后端一体」。** 我先摆清"现在已经是一体的部分"，再叠三种读法，用户选了最重的那种：**一个应用，不是一个网页**。并确认目标是**专用设备**（开机就是这个系统，平常用不到浏览器）。

**然后我核 ADR-0008 时发现它否决桌面应用的两条论证都站不住：**

1. **循环论证**：它写"渲染器必须是浏览器（ADR-0004 §6 的验收项写的就是'浏览器前端同时开启'）"。但那是**测量场景**——要求测内存时浏览器也开着，它甚至在下一句写明浏览器是一笔要交代的额外成本。**把测量假设当设计约束，因果反了。**
2. **内存算术两边不对等**：它否决 Electron 的理由是"常驻 150MB+ 撞 4GB 预算"，**可浏览器也是 Chromium、也是 150MB+**，而 ADR-0008 §5 自己承认浏览器进预算。同一把尺子量两边：旧方案 = Chromium + Node 宿主 ≈ 190–360MB；Electron = Chromium（主进程即宿主）≈ 150–300MB。**被否决的那个反而少一个进程。**
3. 唯一让旧方案划算的前提是"那台设备本来就要开浏览器"——**专用设备上这个前提不成立**。于是旧方案多花内存还换来一个更差的产品：用户要开浏览器、敲地址。

**定案（ADR-0009）**：渲染器 = Electron，**主进程即本地宿主**，通道由 localhost HTTP + SSE 换成 **IPC**（preload 白名单）。Tauri 否决，但**理由不是它差**——它运行时可能最省（WebKitGTK）、磁盘占用小得多——而是**它解决不了本案的问题**：宿主要么重写 Rust（`acp-client` / `spaces` / `model-config` 全重写，丢掉 Node 侧现成 ACP 支持），要么打 Node sidecar，**那仍然是两个进程，而这次的目的正是不再是两个东西**。

### 关键认识：这次能这么便宜，靠的是 ADR-0008 的分层

`agent/` 那 510 行**一行不用重写**。变的是入口（不再起 HTTP server）与传输层（`http.ts` → `ipc.ts`），业务在 `services/`、协议在 `acp-client.ts` 都不动。删掉的比加的多：端口、静态托管、CORS、`EventSource`。

**接触面只有 3 个端点**：`/api/health`、`/api/agent/status`、`/api/agent/chat`。

**ADR-0008 选项判断错了，但分层是对的**——所以新 ADR 里专门写了一节「保留且升值」，否则下个会话会以为可以把整个 ADR-0008 丢掉。

### 连带的几个关闭

- **ADR-0008 §6.1 那条悬置项关闭**：它写"唯一会推翻 HTTP/SSE 的情形是双向高频 + 中途打断生成"——**IPC 天生满足**，不用等。WebSocket 不会再出现
- **ADR-0004 §6 那句"必须在浏览器前端同时开启的场景下测"作废**，且**口径反而更严**：渲染器本来就在被测进程树里，以前那句只是口头约束
- **安全面更紧不是更松**：渲染进程在 `nodeIntegration: false` + `contextIsolation: true` 下，能调的方法只能是 preload 里显式列出的那些。HTTP 时代它对 `/api/*` 是"能发请求就能试"；IPC 时代**连随便发一个请求的能力都没有**
- **一个新发现**：§6.3.3 的 X1 文案里**没有**"浏览器"字样——我原以为要改，核完发现不用。留了条纪律：今后新写的界面文案不得再说"浏览器"

## 一条模式（今天真正的收获）

**四次失真，同一个成因：决策改了，引用它的地方不会自己跟上来。**

| 失真 | 表现 |
|---|---|
| §9.1.1「云端 = 编排 Harness」 | D14 时代写的，卡住 M0 才被发现 |
| 「AI 自动总结」→「周期回顾」 | 规格书改了，原型与代码漏了 |
| 侧栏 small 与页头 p-desc | 实现时压成一条，四处错三处 |
| ADR-0008 的渲染器形态 | **连 ADR 内部的论证本身都是可错的** |

前三条是"改了 A，忘了 B 也在引用 A"。第四条更深一层：**ADR 里的论证也要能被复核**。今天的教训是"谁比谁贵"这类比较要先确认**尺子两边对等**——错误形态是拿候选方案的"新增成本"去比自家方案的"增量成本"，忘了自家也有一项等价成本没算进去。

**动作**：凡新增或推翻一条决策，把同类断言在**文档 + 原型 + 代码**三处各 grep 一遍；凡遇到"因为 X 所以要 Y"的论证，问一句 **X 是哪一类命题**（规定 / 测量场景 / 假设）。文档层已有三套校验器，原型与代码层还没有——`glossary_code_consistency.py` 现成且"有代码后才有意义"，下个收口点该跑它。
