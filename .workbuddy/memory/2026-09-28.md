## 上午：删掉并行样式系统（`ef64b19`）

删了 `src/components/ui/*`（Button / Chip / Input / Switch / Segmented / Panel）与展示它们的 `#kit` 组件库页。

**起因**：用户看过 M0–M2 的成果后说「跟我们之前搭的 demo 完全是两回事」。核下去，根因是我把原型的 Tailwind 工具类**手译**成 React 组件——等于把几百个数值人工折算一遍。走形的证据：侧栏没有选中态竖条、图标是文本字形、聊天页成了占位卡片。

原因写进 DESIGN-SPEC §9.3 并标注「不要再建 `components/ui/`」。

## 傍晚：ADR-0009 —— 渲染器是桌面应用

**用户提出「这个系统我认为还是需要前后端一体」。** 我先摆清"现在已经是一体的部分"，再叠三种读法，用户选了最重的那种：**一个应用，不是一个网页**。并确认目标是**专用设备**（开机就是这个系统，平常用不到浏览器）。

**然后我核 ADR-0008 时发现它否决桌面应用的两条论证都站不住：**

1. **循环论证**：它写"渲染器必须是浏览器（ADR-0004 §6 的验收项写的就是'浏览器前端同时开启'）"。但那是**测量场景**——要求测内存时浏览器也开着，它甚至在下一句写明浏览器是一笔要交代的额外成本。**把测量假设当设计约束，因果反了。**
2. **内存算术两边不对等**：它否决 Electron 的理由是"常驻 150MB+ 撞 4GB 预算"，**可浏览器也是 Chromium、也是 150MB+**，而 ADR-0008 §5 自己承认浏览器进预算。同一把尺子量两边：旧方案 = Chromium + Node 宿主 ≈ 190–360MB；Electron = Chromium（主进程即宿主）≈ 150–300MB。**被否决的那个反而少一个进程。**
3. 唯一让旧方案划算的前提是"那台设备本来就要开浏览器"——**专用设备上这个前提不成立**。于是旧方案多花内存还换来一个更差的产品：用户要开浏览器、敲地址。

**定案（ADR-0009）**：渲染器 = Electron，**主进程即本地宿主**，通道由 localhost HTTP + SSE 换成 **IPC**（preload 白名单）。Tauri 否决，但**理由不是它差**——它运行时可能最省（WebKitGTK）、磁盘占用小得多——而是**它解决不了本案的问题**：宿主要么重写 Rust（`acp-client` / `spaces` / `model-config` 全重写，丢掉 Node 侧现成 ACP 支持），要么打 Node sidecar，**那仍然是两个进程，而这次的目的正是不再是两个东西**。

### 关键认识：这次能这么便宜，靠的是 ADR-0008 的分层

`agent/` 那 510 行**一行不用重写**。变的是入口（不再起 HTTP server）与传输层（`http.ts` → `ipc.ts`），业务在 `services/`、协议在 `acp-client.ts` 都不动。删掉的比加的多：端口、静态托管、CORS、`EventSource`。

**接触面只有 3 个端点**：`/api/health`、`/api/agent/status`、`/api/agent/chat`。

**ADR-0008 选项判断错了，但分层是对的**——所以新 ADR 里专门写了一节「保留且升值」，否则下个会话会以为可以把整个 ADR-0008 丢掉。

### 连带的几个关闭

- **ADR-0008 §6.1 那条悬置项关闭**：它写"唯一会推翻 HTTP/SSE 的情形是双向高频 + 中途打断生成"——**IPC 天生满足**，不用等。WebSocket 不会再出现
- **ADR-0004 §6 那句"必须在浏览器前端同时开启的场景下测"作废**，且**口径反而更严**：渲染器本来就在被测进程树里，以前那句只是口头约束
- **安全面更紧不是更松**：渲染进程在 `nodeIntegration: false` + `contextIsolation: true` 下，能调的方法只能是 preload 里显式列出的那些。HTTP 时代它对 `/api/*` 是"能发请求就能试"；IPC 时代**连随便发一个请求的能力都没有**
- **一个新发现**：§6.3.3 的 X1 文案里**没有**"浏览器"字样——我原以为要改，核完发现不用。留了条纪律：今后新写的界面文案不得再说"浏览器"

## 深夜：v1.5 迁移（桌面壳）—— 已完成并实测

### 关联图那条冲突其实能"解开"而不是二选一

核的时候发现 **§6.2 自己就已经把两件事分开了**：它的三档里「**关联计算**」在**云端往返**那一档、「**重排图谱**」在**本地有耗时**那一档。所以只有 §5.1 的一句在混。

定案 **D34**：**语义分析（谁和谁相关、多强）走云端大模型；坐标（把已知强度摊成二维位置）在本地算**。用户说的是"调用云端大模型来**分析**"，而**分析确实是云端的事**——但**大模型不产出坐标**，力导向是数值迭代，拿语言模型算坐标既贵又不稳。两条都对，只是不是同一件事。

### 迁移实测（不是推断）

先说一个省掉整层工作的发现：**Electron v44 内置 Node 24.21.0，`process.features.typescript === 'strip'`** —— 主进程与 `node agent/index.ts` 是同一个机制，**不需要任何构建步骤**，新依赖仍然只有 `electron` 一个。（`preload` 例外：它跑在渲染进程沙箱里、不走 Node 加载器，所以是普通 `.cjs`，只做转发。）

写了 `electron/selftest.ts`（`npm run selftest`）。**桌面壳的问题是静默失败**——窗口开出来了、页面也画了，但桥没挂上、方法名拼错、白名单太宽，肉眼看不出来。四项全过：

| 检查 | 结果 |
|---|---|
| `window.host` 桥挂上了 | `bridge: true` |
| `health` 往返 | `{ok:true, uptimeSec:1, agentConnected:false, space:"我的空间"}` |
| `agent.status` 往返 | `{installed:true, initialized:false, hasSession:false}` ← **`initialized:false` 证明懒启动没被误触发** |
| **白名单外的方法被拒** | `whitelist: "rejected"` |

最后一条是**安全属性**，必须验——它一旦悄悄失效，能力面就变宽了，而没有任何表现。主进程日志确认拒绝来自方法表：`Error: 未知方法：__not_in_table__` at `electron/main.ts`。

### 迁移的账：删掉的比加的多

删：端口分配（`shared/ports.ts`）、静态产物托管（`static.route.ts`）、CORS、`EventSource` 重连与那个 15 秒 keepalive、`routes/` 整个目录、`lib/http.ts` 整个文件、`agent/index.ts`（旧 boot）。

**净减约 145 行。`agent/services/` 与 `acp-client.ts` 一行没改。**

**这正是 ADR-0008 把宿主收在 `agent/` 一个根里的红利**——换壳只动"入口 + 传输"两处。ADR-0008 的选项判断错了，但分层是对的，所以 ADR-0009 才能这么便宜。

### 三个踩到的坑（都记进 MEMORY 了）

1. **生产态必须 `base: './'`**：窗口用 `file://` 加载 `dist/index.html`，绝对路径资源会被解析成文件系统根。不加就是白屏
2. **流式调用不能用 `await` 判断结束**：HTTP 时代 `await fetch` 会一直等到流结束；IPC 的 `stream()` 立即返回，所以"结束"必须由事件决定（`agent.done` / `agent.error` / `host.error` 三条终态各收一次尾）。照抄旧结构会让 `busy` 立刻被清掉
3. **`AgentStatus` 的形状要归 `shared/`**：它原本定义在 `agent/services/` 里，而渲染器要消费它。放 `agent/` 会让渲染器 import 宿主实现（拖进 node 依赖）。已挪进 `shared/types.ts`，宿主改为 import 它——**线上形状归 shared，宿主只是产出者**

### 第一批设计决策（2 条，都用 ask 定下）

**D36 · `gateway` 字样**：**从用户可见文案里删掉它**。§6.3.3 的 X1 技术细节行改「**模型服务**」——与标题**同词**。原先标题写"模型服务"、细节行写"gateway"，是**同一概念两个词**；而且 `gateway` 对用户**不可指**（他既看不见那个进程也管不了它）。它**从来不是本产品术语**，是借来的词。

**全库已清**（规格书 5 / 原型 1 / ADR 0002·0003·0004·0006 共 5 / `.impeccable.md` 2 / M0 清单 2）。**这是术语清理不是改写历史**——与「知识库」→「知识空间」那次同例，所以 ADR 的散文也一并替换；带日期的快照保留原样。

**D35 · 关联何时算数（ADR-0010）**：**分「已建立关联 / 候选关联」两态**，中间是一条**可调**的**关联阈值**。

这条值得记下推理过程——**它本来是个两难，两边都有已定案的东西顶着**：

- 一边是 D15 / §9.1.2：「决策层**未校准前不允许自动写入图谱**」
- 另一边是产品核心差异：Obsidian 靠手写双链，我们靠 **AI 自动建关联**；若一切先问而用户不处理，**核心差异永远看不到**

**两句话直接对撞，说明缺的不是"选哪边"，而是"关联只有一种状态"这个假设本身。** 两态把它变成 **"阈值定在哪"**，而阈值可调 → **未校准期间拉满即完全满足 D15**，校准后逐步放开。同一个机制覆盖 D15 的现在与产品的将来。

三条推论：① **「候选不进图谱」是定义性的**（唯一的区别就是还不许出现在图谱里，否则两态毫无意义）；② 与**来源关系**的分工不变（前者蒸馏自动产生、不可否认；后者 AI 提议、可否认），两态只把"提议"拆成"已算数"与"还在等"；③ **必有 `confidence` + `decidedBy`** —— 阈值可调 ⇒ "当初为什么算数"必须可追溯，否则阈值只是个会静默改行为的魔数。

术语表新增 **已建立关联 / 候选关联 / 关联阈值** 三条（27 → 30）。

### 踩到 / 发现的两件事

1. **术语表校验器抓到我一次错**：新加的两个状态术语，定义行**以加粗开头**（`**关联**的两个状态之一：…`），被解析器当成了又一个术语，报 `term-definition` FAIL 2 条。改成以普通文字开头（"两个状态之一（另一个是…）"）即过。**这就是那个校验器存在的意义**——它有它自己的格式假设，猜不得。
2. **⚠ 一核就发现「候选关联的入口」很可能是重复 UI**：§5.2 进化图谱**早就有「待确认卡片」**（"陶色左竖条 + 待你确认，是唯一需要用户决策的类型"，数据里叫 `needsConfirm`），而 §5.2 自己的待定项里就写着「待确认项怎么操作」。**候选关联由关联器产生，而关联器的一次运行就是一条演化记录**（ADR-0001）——若两者是同一个东西，则**不需要新 UI**，只需对齐口径 + 决定 `needsConfirm` 挂在演化记录（派生）还是产出物上。**这条不定，"候选关联的入口"会变成第三处重复 UI。**
