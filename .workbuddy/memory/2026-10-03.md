## 一、Mock 怎么放：把假数据从渲染器收拢到宿主

原来假数据散在**三处**：`src/features/files/demo.ts`、`src/features/summary/demo.ts`，**外加 `App.tsx` 里写死的 `SPACES`**（这个最隐蔽，看着像"产品还没有空间"这个正常状态）。页面**绕过接口直接 import**。

**这条路要拆掉，理由是它掩盖接口问题：页面显示的"对"，证明不了接口是对的。**

现在的结构：

```
agent/
├─ mock/seed.ts       # ★ 唯一一处夹具，类型由 shared/types.ts 约束
└─ store/
   ├─ index.ts        # 接缝：一行决定用内存还是将来的落盘
   └─ memory.ts       # 内存实现
```

- **开关 `--mock`**；不带它 = **空态**，那本身也是要看的界面（§6.3 的 E1）
- **必须可见**：`HealthPayload` 加 `mock: boolean` → 状态栏显示「示例数据」。**假数据不可见就会被当成设计**
- **夹具不会退场**：将来退成两个正式用途 —— 新装设备的示例知识空间、端到端测试的固定输入

**"哪些字段要填示例值"没有单独列清单**，因为**答案就是 `shared/types.ts`**：夹具的类型由它约束，编译器逐字段要求，**而且这清单不会随文档过时**。

存储层是**接缝**：`store/index.ts` 一行决定实现，`store/fs.ts` 来了之后 **`agent/ipc.ts` 一个字不改**。

## 三、★ 这一轮最重要的收获：**四个 bug，全是截图看出来的**

`tsc` 全过、`selftest` 28 项全过之后，截图暴露了四件事：

| 截图暴露的 | 根因 |
|---|---|
| `项目` 文件夹显示 **0**（它有 2 份素材，在子夹里） | `materialCount` 只数**直接子级** —— 界面上和空文件夹一模一样，用户会以为东西丢了。改成**子树计数** |
| 关联图**首屏空白**（有 6 条已建立关联） | 圆心取 `selectedId`，而它初始是 `null`。**默认取关联最多的那个** —— 它天然回答"该从哪儿看起" |
| 状态栏 **`0.0 / 10 GB`** | 写死 `(bytes / 1GB).toFixed(1)`，而夹具只有几 MB。单位要跟着量级走（`formatBytes`） |
| 切「知识点」报 **`未知的视图：undefined`** | 素材视图的查询在知识点模式下也在跑，而 `VIEW_OF` 里没有 `know` |

**结论：类型与断言管得住"功能对不对"，管不住"长得对不对"。一期必须三步都跑**（`selftest:mock` / `shots` / 不带 `--mock` 的空态）。

还修了一处**移植错误**（也是截图才看出来的）：`ContentShell` 把 `bodyClass` **替换**了 `.p-body`，而原型写的是 `#page-files .p-body{...}` —— **它是叠加**。撑开高度的是 `.p-body{flex:1;min-height:0}`；换掉它，文件页的视图区只剩内容高度，关联图被压成一小块、视图区冒滚动条。`settings-body` 有同一个病。

> **这类错的形态**：从原型移植时，把"**在基础类之上叠加**"改成了"**用页面类替换基础类**"。
> 原型的选择器里 `<页面> .<基础>` 这种写法是在告诉你**两者都要在**，别读成"只要后者"。

## 四、几个技术坑

1. **`Omit` 对联合类型不分发**：`Omit<Material | KnowledgePoint, K>` 取的是 `keyof (A|B)`，而**联合类型的 `keyof` 只剩公共键** → 会静默吃掉 `folderId` / `body` 这些只在一边有的字段，**夹具写成什么样都能通过**。改成 `SeedMaterial` / `SeedKnowledge` 两个具体类型（分开写之后，缺字段当场报错）
2. **自检断言写反了**：`why()` 判的是"应该抛错"，而"清理回原状"要的是"不该抛错"，于是它把一个**成功**判成了失败。补了 `fine()`
3. **页内状态在切 hash 时保留**：所以 `files-know` 必须排在 `files-graph` 之前，否则拍出来的是"知识点胶囊 + 关联图"
4. **截图要锁亮色**：应用默认跟随系统偏好，而开发机是暗色；原型截图是无头浏览器拍的（默认亮色）。不锁就没有可比性

## 五、纪律新增

- **截图分两处，别混**：`design/prototype/shots/` 是**基准**，`design/app-shots/` 是**实现**。混在一起"基准"就失效了 —— 改实现时不小心覆盖基准，就再也没法比
- **`git commit` 走消息文件**（`-F`），别用 `-m` —— 这条老纪律今天再次生效

# 下半场 · S2 知识总结页

## 做了什么

删掉 `src/features/summary/demo.ts`，页面全部走宿主：统计卡四张 + 热度柱 + TOP 6 来自 `stats.summary`（S1 已实现），周期回顾来自新写的 `review.get`。接口 **27 → 28**。

- **分桶**：`span` 是**每条条目的粒度**，不是"只看这一段"——日档列出最近几天、周档列出最近几周，一个桶一条，**空桶不出现**（画出来只会让人以为系统在骗他）
- **缓存**（D43）：键 = 时段 + 当前桶 + **内容指纹**（知识点 id+updatedAt+deletedAt、关联 id+state、演化 id 的短哈希）。带指纹的好处是**不需要在每次写操作里手写失效逻辑**——也就不会漏
- **有界**：键会长（时段×桶×指纹），32 条 FIFO，超了丢最旧的（重生成很便宜）

## ★ 这一期最重要的一个决定：**故意留了半个缺口**

D43 定的是「周期回顾由**生成层**在打开那一刻写」。那条路要 agent 运行时 + 模型凭据，**当前开发环境跑不起来 —— 也就没法验收**。

所以我只实现了另一半：**本地按演化记录数出事实**（`source: 'local'`），并在 `ReviewResponse` 上加了 `source: 'model' | 'local'`，界面在面板下方如实标注。

**为什么不把模型那半也写了**：那会是一段"看着能用、其实没人跑过"的代码。本项目反复吃过这个亏（假数据不可见就会被当成设计）——**同一把尺子**：不可见的实现也会被当成实现。接的位置、提示词该怎么给事实、失败怎么落，都写在 `agent/services/review.service.ts` 末节。

`source` 这个字段的作用就是**让缺口可见**：接上之后翻成 `model`，界面那行标注自动消失。与 `HealthPayload.mock` 是同一个手法。

**推论：本地这版只报事实、不写叙述。** 没有形容词、没有"看出趋势"——那是模型读内容之后才有资格做的事，本地数数没这个资格。

## 新增的一条纪律

**空态截图与夹具截图必须并存**：`--shots` 带 `--mock` 存原名，不带则存 `-empty` 后缀。原来两者同名，后跑的会覆盖前一套，于是"两套都看过"变成"看过最后跑的那套"。而**空态是另一套界面**。

# 第三场 · S3 聊天页（◐ 半程：数据面做完，两处视觉留给设计）

## 做完的

删掉页面里的本地 `msgs` 假状态，接上真实的**对话历史**（D38）：

- 首屏落到**最近那段**对话上（历史是要看的，不该默认空着）
- 发话**之前先建对话** —— 宿主得有个门牌号才知道往哪写。这一步放在页面而不是宿主，因为"要不要新开一段"是**用户的意图**，不该由宿主替他决定
- 消息由**宿主**写：`agent.chat` 收到 `conversationId` 后，**跑 agent 之前**先写用户那条，成功后才写助手那条
- 流式的那半截**不落历史** —— 它是草稿，不是这次对话发生过的事
- 结束后**以宿主为准**重读一遍，本地那份只是过程中的临时显示
- 标题自动取第一句用户话（用户不必先给对话起名再说话）
- 空态那行状态改成真的：`AI 就绪 · 已索引 8 个文件 · 6 条关联`（读 `stats.summary`）

**白名单里故意没有 `conversation.append`**：渲染器若能自己写历史，它的本地副本与真实历史就能分叉，而"分叉之后谁对"没有答案（ADR-0008 边界 2：宿主是唯一写入者）。自检里有一条断言专门守它。

### 教训（比这一期的代码值钱）

**不要凭"我觉得环境里没有 X"就写下一条理由 —— 去测一次。**

这句话听起来像常识，但它的形态很隐蔽：当时我是在**为"不做某件事"找理由**，而"环境不具备"是最省事的理由 —— 它把责任推给环境，不需要我再做任何事，而且**听起来很负责任**（"不写没测过的代码"）。

**一个错的理由比没有理由更坏**：它会让人以为"等换了环境就能做"，于是那件事会被无限期地挂在一个**永远等不到的时机**上。

已在 `docs/接口规范.md` 原地更正（保留原文 + 更正节），因为删掉它就看不出"曾经是这么想的"。

## 撞出一条新未定项：**知识空间的磁盘布局**（登记为 S5）

整条存储层现在是内存的，所以"重启后没有"是**全库一致的现状**，不是缺陷。但落盘会引出真问题：

- 产品自己的数据（知识点/关联/演化记录/对话历史/索引）落在**内容根里面**（`.space/`）还是**外面**（应用数据目录）？
- 素材元数据**另存一份**，还是**写在素材文件的头里**？（后者让用户在 Finder 里直接编辑也带得走）
- 一坨 JSON / 一行一条 JSONL / SQLite？

**它影响每一个将来要持久化的实体**，目标机是专用设备（备份与迁移都挂在它上面），且设置页空着的「**存储与同步**」模块直接吃这条决定。按纪律：**先改文档再改代码**，不猜。
