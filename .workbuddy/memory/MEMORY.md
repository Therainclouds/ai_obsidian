# 项目长期记忆 · AI 知识系统

## 项目是什么
个人 AI 知识系统（Obsidian-like + AI 助手）。核心差异：**关联由 AI 自动建立**（Obsidian 靠手写双链），图谱展示「演化过程」而非链接快照，对话是主入口。
6 个模块：① 聊天 ② 文件管理 ③ 进化图谱 ④ 知识总结 ⑤ 设置 & 我的 ⑥ 全局 AI 悬浮球 + 小窗。

## 领域模型已定案
- **知识点 = AI 的整合产出**（整合聊天/素材后的总结，带知识点标签），**不是原始内容**。
- 因此关系分两层，**不得合并计数**：
  - **来源关系**：知识点 ← 素材，方向固定，蒸馏自动产生，用户不能否认
  - **关联**：AI 发现的相关性，用户可确认/否认
- **演化记录 = 事件模型**：`trigger + inputs[] + outputs[]`，不是固定三段链。
  - `trigger` 必须是四个 Hook：收集器 / 解析器 / 关联器 / 沉淀器（原稿漏了收集器）
  - 卡片布局由 `inputs.length × outputs.length` 决定，不由下标决定
  - 不变量：一次演化至少产出一个实体或一条关联，产出为空的是日志不是演化
- **决策层 ≠ 生成层**：决策层只做判断、返回类型化答案 + 置信度（候选载体：Jev / Open-Jev）；生成层才写字。沉淀器两者都要用 → 设置页因此有**两个模型位**，分设、不得合并。
- **编排分治**（ADR-0002）：聊天由 Hermes 自主驱动；四个 Hook 由我们的 Harness 编排，Hermes 只在"该写字"那步被叫进来。原则：**不给不确定的东西以编排权**。副作用：收集器/解析器零 token。
- **agent 运行时 = Hermes Agent**（`hermes acp`，ACP JSON-RPC over stdio），home 在 `~/.hermes/`。**进程跑在设备本地**，与知识库同机（ADR-0004），不提供云端模式。
- **技能分两个命名空间**（ADR-0005 + 修订）：**产品技能 1 个**（沉淀器的写作规范——住我们仓库、产品点名、可 review）；**用户技能不限**（住 `~/.hermes/skills/`、agent 自主触发、产品不 review 但必须在设置页可见可停用）。Hermes 官方把 skill 列为**高信任载体**（"等价于本地主机代码，可读环境变量、可执行任意命令"），所以安全靠**能力隔离**而非禁令。
- **知识空间 ≠ profile**（ADR-0006）：**知识空间**是内容边界（文件树/知识点/关联/演化记录，用户可建多个）；**profile** 是 agent 身份（运行记忆/技能/config，默认只有一个，全部空间共用）。
- **内容实体边界**（ADR-0007，2026-09-23）：判定标准是**「它有没有走一次演化」**——走了的是实体，没走的是**视图**（不进图谱、不产生来源关系、不计入统计）。三个应用：**对话 = 素材的子类**（术语 `对话素材`，无文件夹、不进文件树，只作来源）；**周期回顾 = 视图**（总结页的日/周/月条目，**不是**知识点，改名自「AI 自动总结」）；**「全部」胶囊 = 只数文件素材**。`kind` 只有 `material | distilled` 两个取值，对话素材靠 `folderId === null` 区分。
- **宿主形态**（ADR-0008，2026-09-23）：**本地 Node 宿主**。设备本地 = **渲染器 + 本地宿主 + agent 运行时**（三者同机）；云端只剩**决策层 + 生成层**——只有算力在云端，**编排不在**。宿主是**知识空间唯一的写入者**，agent 运行时是它拉起的**子进程**。原 §9.1.1「云端 = 编排 Harness + …」为 v1.0 旧句，**已撤销**。
- **渲染器形态**（**ADR-0009**，2026-09-28）：**它是一个应用，不是一个网页**。渲染器 = **Electron**，**主进程就是本地宿主**，通道由 localhost HTTP + SSE 换成 **IPC**（preload 白名单）。四个根：`electron/`（只有入口与桥）· `src/`（渲染进程）· `agent/`（宿主，跑在主进程里）· `shared/`。**ADR-0008 的"本地 Node 宿主 + 浏览器"被推翻，但它的分层保留**——`agent/` 一行没重写，换的只是外壳。**Tauri 否决的真实理由**：它要么把宿主重写 Rust、要么打 Node sidecar，**那仍然是两个进程**，而这次的目的正是不再是两个东西。
- **关联分两个状态**（**ADR-0010**，2026-09-28）：**已建立关联**（置信度**过关联阈值**，进**进化图谱**）/ **候选关联**（没过阈值，**不进图谱**，只在图谱页一个显式入口里可见）。中间是一条**可调**的**关联阈值**——**未校准期间拉满 → 全部落候选**，于是 D15「未校准前不允许自动写入图谱」自动满足，而校准后可逐步放开。**"候选不进图谱"是定义性的**：它唯一的区别就是还不许出现在图谱里。**与来源关系的分工不变**（来源关系蒸馏自动产生、不可否认；关联 AI 提议、可否认）——两态只把"提议"拆成"已算数"与"还在等"。**必有 `confidence` + `decidedBy`**：阈值可调 → "当初为什么算数"必须可追溯，否则阈值只是个会静默改行为的魔数。
- **两份历史，两个词**（**D38**，2026-09-29）：**对话历史** = **产品自己存**的对话集合（术语，新增）；**会话** = **agent 运行时**的私有记录（`state.db`），**产品不读它**。原先 `ADR-0007` 写"未蒸馏的对话只活在聊天页的**会话历史**里"——**两份不同的历史用了同一个"会话"字样**，看起来像产品在读 `state.db`。已为产品那份立词。
  **顺带修掉一处更早的范围不一致**：`对话素材` 原定义写"**被一次蒸馏引用过的**对话内容"，与 `ADR-0007`「对话**是**素材」对不上。已定：**全部对话都是素材**；**"露不露"（进不进知识视图）与"算不算"（是不是素材）是两回事**。
- **「待确认」挂在演化记录上，不挂在产出物上**（**D37**）：`needsConfirm` 在**演化记录**上、由产出**派生**；关联的**状态**（已建立/候选）在**产出物**上。**两个维度两个字段**。好处：以后加新的可确认物（"是否建主题簇"）不改结构。**副产品**：**候选关联的入口就是已有的「待确认卡片」**，不需要新 UI —— 关掉了一次"第三处重复 UI"的隐患。
- **对话历史的列表 = 聊天页内可收起的左栏，默认收起**（**D39**）：聊天页的视觉基准是**居中满屏、无页头**（§4.3）——常开的第二栏会改掉这条基准，而**收起态能与原型逐像素一致**。全局侧栏已装"知识空间切换器 + 5 入口 + 主题切换"，再塞会长得离谱。
- **小窗与主聊天是同一段对话的两个窗口**（**D40**）：与 §4.2 的"同一个 AI、**同一份上下文**"一致，与"**对话历史每个知识空间一份**"（D38）一致。**小窗是入口，不是另一个会话** —— 它不产生第二条对话。
- **AI 回复只展示「依据」卡片，不展示推理过程**（**D41**）：推理过程是 agent 的**内部草稿**，与「**运行记忆**不露出」同源——展示它等于把没被校验过的草稿变成**产品承诺**。
  **⚠ 配套一条术语纪律**：**回答的「依据」不是来源关系**（来源关系要求一端是**知识点**，而一条回答不是知识点），**不得叫「引用来源」**——「引用」是**来源关系**的 `_Avoid_` 词。数据上它是那条**演化记录**的 `inputs[]`。同一批还清了规格书里别处的「引用」误用（"AI 引用次数"→"调用次数"、"引用知识"→"带上知识点"、原型里两处文案）。
- **「AI 整理」= 手动补跑「解析器 + 关联器」**（**D42**）：只处理"**尚未解析**的素材"与"**尚未算关联**的节点"。**不新增 Hook**，只是给已有两个 Hook 补一条手动触发路径。**它回答的是"我塞完文件后它怎么不动"**。归类 / 打标签 / 去重**三者都不在这个按钮里**（前两者要动 D11 定的用户文件夹结构，第三者是不可逆的内容操作）。推论：**幂等**（没待处理项时按钮应**禁用并说明**）、属于**云端往返**要有完整三态。
- **周期回顾 = 打开时现生成 + 缓存**（**D43**）：**不加调度器**——进程拓扑（§9.1.3）里没有这一层，为"打开时更快"多一层常驻逻辑与一套任务失败错误态不划算；且**推理全在云端、每次都花钱**，没人看的时段不该跑。
  **关键边界**：**缓存 ≠ 落盘为实体**。ADR-0007 的"周期回顾不落盘"指**它不成为内容实体**；缓存是**派生数据的副本**，随时可丢。失效规则 = 该区间的**知识点集合变了就失效**；缓存放**内存（会话级）**，落盘与否留待实测。
- **Hook 关掉后历史演化记录保留如常**（**D44**）：开关管"**以后还跑不跑**"，不管"**历史里有没有过**"。**与「失败不毁内容」同一立场**——不因当前设置变了就改动已写下的记录。推论：关掉某 Hook 后图谱里它产生的节点与边**照旧在**，只是不再新增。这让 ADR-0007「图谱只收走过演化的东西」更站得住：**收的是事实，事实不随开关回退**。

## 已定案，不可随手改
- **主色 = 靛 Indigo**（`#3B4CC0` / dark `#88A0F6`）。历史路径：青 Jade（否决）→ 三候选 → 定案靛。
- **三色体系，零第四色**：墨（结构）/ 靛（行动）/ 陶（提示 `#B35618` / `#E58C5B`）。
- **状态语义色也走三色**：成功 = 主色 / 需注意·失败·待配置 = 点缀色 / 中性 = 墨灰。**不引入红绿黄。**
- **配色黄金律三条**：面积比 60:30:10；中性面与主色同色相、彩度 ≤0.014、只动明度；点缀色 = 主色 H + 137.5°。**色值必须由 `palette-gen.py` 生成，禁止手工改色值。**
- **动效锁定「克制档」**：只留 L1 系统层 + L2 交互层，L3 氛围类（极光/粒子/火花/磁吸）永久禁用。
- **缓动只用 easeOut 系**，禁用弹性回弹（back/elastic）——这是"AI 味"的主要来源。
- **导航项必须「图标 + 名称 + 一句话解释」**，禁止只放名词让用户猜。
- **「主色实底 + 文字」必须用 `var(--on-brand)`**，不得写死 `#fff`（暗色下主色是浅色）。
- 主题：`<html data-theme="light|dark">`，首屏前内联注入防闪白。
- **工具集白名单**（ADR-0002 + 0005 修订，硬约束）：开 `file`·read/search、`skills`、`session_search`、`vision`；`file`·write 仅限 `~/.hermes/`；**关 `terminal`/`execute_code`**（素材是不可信输入）、`web`/`browser`/`memory`/`todo`/`delegate_task`。**不照抄 multica 的 `HERMES_YOLO_MODE=1`。**
- **cwd 恒为「当前知识空间」的根**，不暴露到设置页（安全边界，不是偏好）；改 cwd 只允许在 `agent/spaces.ts` 一处。
- **模型配置的单一事实来源 = Hermes 原生配置**（`config.yaml` + `.env` + `auth.json`）；设置页做受限读写，优先 `hermes config set`，fallback 才改文件且须保留注释。**密钥单向：可写不可读。**
- **运行记忆 ≠ 知识点**，严格分名分物；**不读 `state.db`**，对话素材自己存。
- **写入边界按作用域切**（ADR-0005 修订）：**知识空间根只读**、**`~/.hermes/` 可写** —— 一句话「**agent 可以改自己的脑子，不能改用户的资料**」。演化记录一律由 Harness 写，即使 agent 自主触发了技能也没有写权限。
- **进程拓扑不可随手改**（ADR-0008）：宿主是知识空间的**唯一写入者**；agent 运行时是宿主拉起的**子进程**（宿主退出它就该退出，避免"一个 home 两个 agent"，ADR-0002 §5）；cwd 解析只允许在 `agent/spaces.ts` 一处；**M0 内存实测口径 = 宿主 + Hermes 两个进程之和**。
- **Harness / 本地宿主 / agent 运行时是三个词，不得混用**：**Harness** = 产品侧编排层（跑在宿主里）；**本地宿主** = 承载它的 Node 常驻进程；**agent 运行时** = 宿主拉起的 Hermes 子进程。
- **产品技能**：正文不出现时序词、由 Harness 点名、不放脚本、不声明 `env_passthrough`（高信任载体，能读环境变量 = 密钥面打开）。
- **用户技能**不受上述约束（那些是给"点名调用"做的前提）；产品只需三项义务：**标记来源 / 拦截脚本面 / 告知 token 成本**。
- **「成长轨迹」不是术语**：内容的成长 = 演化记录（进图谱）/ agent 的成长 = 运行记忆 + 用户技能（不进图谱）。**两者不得画进同一张图**——那会让"AI 自己记的"看起来像"我的知识"。
- **「重载 agent」是唯一的生效动作**：模型配置 / 技能变更 / 知识空间切换三处合并，设置页只出现一次。
- **素材类型是文件事实**（MIME / 扩展名 / 文件头），不是判断 → 解析器不需要模型，定不了标"未识别"。
- **网络边界：局域网设备**（2026-09-23 澄清）—— 本机 ↔ agent / 知识空间**零网络跳**，唯一的网络依赖是**公网出口到云端模型**。**不承诺离线操作**：不设离线模式 / 离线横幅 / 离线队列。要区分的是「这一下要不要出网」，不是「在线还是离线」。
- **推理全在云端 → 三态是主路径不是异常**（每次调用都是一次公网往返）。
- **三态按「数据来源」分流，不按页面**（v1.1 §6.3 定案）：纯本地动作（切页/切筛选/展开文件夹）**不给加载态**——加了就是撒谎；本地耗时只给骨架；云端往返给完整三态。**禁止转圈**（例外：AI 已在流式出字）、**禁止假进度**。
- **空态分四型，不可合并**：E1 首次（≤3 个并列入口）/ E2 中性 / E3 筛选后 / E4 搜索无果。**E3/E4 绝不能写「还没有内容」**（东西还在，只是没露出来）。**错误分五型**（不可达/鉴权/额度/内容/本地），两条铁律：**失败不毁内容**（stale-while-error）、**局部失败 ≠ 整页失败**。
- **「AI 正在做」是一等状态，不是普通加载**：三段阶段回显（读取素材→整合关联→写知识点）**正对应演化记录的 trigger** → 聊天与图谱看到的是同一件事；完成后折叠成一行痕迹。
- **失败不毁内容**（取代 v1.1 的「离线降级」，2026-09-23 撤销）：① 用户写的**不丢**（消息留在对话里、草稿不清空、不弹遮罩不锁输入框）② 已渲染的**不清空** ③ 失败**可继续**（错误条内联重试）。X1 = **模型服务不可达**，挂**对话流里的 `.msg-err`**、**没有全局态**——错误属于"那次操作"不属于"整个产品"。文案**不说"网络错误"**（用户在局域网里，会把他引去查路由器）。
- **新建知识空间后的空**是全套三态最重处：树栏轻提示 / 主区 E1 起步引导 / **图谱页保留 Hook 开关与通道示意、只空轨迹区**（通道不是内容）。空态里通道示意数字必须**归零**，否则与"空"自相矛盾。
- **原型三态直达**：`index-final.html#unreachable` `#loading` `#empty` `#filtered` `#error`（可逗号组合）。

## 工作方式约定
- 改视觉参数的顺序：**先改原型 → 再改 DESIGN-SPEC → 最后改代码**，不可颠倒。
- SVG 里不要用表现属性 `fill="var(--x)"`，统一内联 `style="fill:var(--x)"`。
- 原型改动后跑 `python design/prototype/_check.py`（标签平衡 / CSS 括号 / var 引用 / 重复 id / 内联脚本语法）。
- **改完必实机截图**：`python design/prototype/_shot.py`。三个坑——`--screenshot` 必须绝对路径；页面有淡入动画须注入 `animation:none!important`；**只禁 animation/transition，不可碰 opacity**（`.page` 的显隐就靠 `opacity:0`，强加 `opacity:1` 会让所有页面同时可见）。
- **同一文件的多处修改必须串行发 Edit**：并行发多个 Edit 会丢更新（实测只落最后一个，前几个被覆盖）。改完用 grep 复核。
- **术语机械替换前必须先 grep 上下文**：有三类目标词**不能**碰——① `CONTEXT.md` 的 `_Avoid_` 禁用词列表 ② ADR 里**引用用户原话**（改引用 = 篡改）③ 描述该次巡检自身的待办行。做法：先 replace_all，再把这几处改回。

- **ADR 里的"谁比谁贵"必须复核尺子是否对等**（2026-09-28 教训）：ADR-0008 否决 Electron 的理由是"常驻 150MB+ 撞 4GB 预算"，可它采纳的方案里**浏览器也是 Chromium、也是 150MB+**——同一把尺子量两边，被否决的那个反而少一个进程。**这类错误的形态是**：拿候选方案的"新增成本"去比自家方案的"增量成本"，而忘了自家方案也有一项等价的成本没被算进去。另一条同源：ADR-0008 用"ADR-0004 §6 要求浏览器同时开启"证明"渲染器必须是浏览器"——**那是测量场景，不是形态规定，属循环论证**。**凡遇到"因为 X 所以要 Y"的论证，都问一句：X 是哪一类命题（规定 / 测量场景 / 假设）？**
- **推翻一条 ADR 时，先找它里面"仍然对"的部分**：ADR-0009 之所以只花约 150 行就推翻了 ADR-0008，是因为后者把宿主逻辑收在 `agent/` 一个根里。**分层是对的，只有选项判断错了**——写新 ADR 时把这条红利明确写出来（"保留且升值"那节），否则下一个会话会以为可以把整个 ADR-0008 丢掉。

- **git commit 用 `-m` 且信息里含引号会被 PowerShell 吃掉**：中文引号安全，**英文 `"` 会截断参数**，导致 `git commit` 把后半句当成 pathspec 而失败（工作区看起来"没提交"）。做法：把信息写进临时文件，用 `git commit -F $file`。
- **判断 `git push` 成没成，只看 `git ls-remote origin refs/heads/main`，不要靠输出文本匹配**：PowerShell 会把原生命令的 stderr 包成错误记录，文本里含 `NativeCommandError`——而 `-match` **默认不区分大小写**，`'error'` 会命中它，于是**每次成功都被判成失败**（实测：我因此误报了一次"推送全部失败"，其实第一次就成功了）。同理 `git --no-pager status -sb` 的 `[ahead N]` 标记比任何文本匹配都可靠。

### 🚨 最该先做的一件事：核设备的图形栈（2026-09-28 实测暴露）
ADR-0004 / 0008 / 0009 **一直在算内存，没有任何一条问过"设备有没有 X11 显示服务器"**。而 Electron 不是 framebuffer 程序——`libgtk-3` / `libX11` / `libxcb*` / `libXcomposite` 那一整族都是**硬依赖**，无头设备上它**直接不成立**。这比内存更容易一票否决。

**退路（诚实说）**：若设备确无图形栈，**ADR-0008 的"宿主 + 局域网浏览器"反而是唯一活得下来的方案**，代价是宿主得监听非 localhost、安全面要重估。这是旧方案唯一比新方案强的情形。

**核法**（在设备上，几分钟）：
```sh
uname -m                       # 必须 aarch64
ldd --version | head -1        # glibc ≥ 2.25（实测自 ELF 符号版本）
echo "$XDG_SESSION_TYPE"; ls /tmp/.X11-unix   # 有没有显示服务器
ldd ./electron | grep 'not found'   # 最直接
```

**Electron 44.4.5 linux-arm64 实测数字**（官方 zip，非文档抄录）：下载 118.3 MB → **解包 287.3 MB**（`electron` 单文件 210.6 MB）；glibc 底线 **2.25**；可裁到约 250 MB。完整依赖清单在 `docs/M0-行动清单.md` §3.2。
