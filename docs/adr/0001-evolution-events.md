# 演化记录采用事件模型，而非固定三段链

演化图谱的最小单位是「**演化记录**」，形状为 `trigger + inputs[] + outputs[]`，而不是规格书原稿里的固定三段链「对话 → 文件 → 知识点」。原稿把**实体**、**关系**、**产出**三种不同性质的东西塞进同一个位置，前端拿到扁平数组只能按下标猜角色；而且它装不下真实形状——一次蒸馏可能整合 N 个素材（扇入），一次收集可能一次入库 N 个文件（扇出），两者用同一条三段链画不出来。另外原稿的 `trigger` 枚举只有 `parser / linker / distiller` 三个值，漏掉了**收集器**，等于四个 Hook 里有一个天然无法产生演化记录。

## Considered Options

- **固定三段链（原稿）** —— 卡片形状统一、实现最省。放弃原因：表达不了扇入扇出，且丢掉了「谁触发」这条信息。
- **只记关系变化（edge-diff）** —— 模型最省，演化图谱退化为"一批新建的边"。放弃原因：「AI 做了什么判断」这个信息会永久丢失，而这正是本产品要给用户看的东西。
- **事件模型（采纳）** —— 多一个 `trigger` 字段的成本，换来输入、输出两侧都能表达 1..N。

## Consequences

- `trigger` 的枚举必须是四个 Hook：收集器 / 解析器 / 关联器 / 沉淀器。
- 卡片布局由 `inputs.length × outputs.length` 决定（1×1 直连、N×1 折叠、1×N 展开、0×N 只画产出），不由数组下标决定。
- `confidence` 是**可选**字段：只有关联器与沉淀器这类 AI 判断才有；收集器入库没有置信度。
- 不变量：一次演化记录至少产出一个实体或一条关联。产出为空的事件（"解析器读了 5 个文件、没发现新东西"）不进演化流。
- 总结页「今天 · 3 次演化」中的数字 = 演化记录条数，不是链接条数。
