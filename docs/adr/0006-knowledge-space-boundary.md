# 知识空间是内容边界，不是 agent 实例

「知识空间」在原型里一直只是个侧栏分组标题，不是实体。而 Hermes 有 `profiles/<name>`——官方定义是"隔离实例"，独立记忆、独立技能、独立 config。这两个东西是不是同一个维度？这个问题决定：**一个用户能开几个知识空间**，以及侧栏那个标题是留、是删、还是变成别的东西。

结论：**它们不同维度，默认解耦**。知识空间管**内容归属**，profile 管 **agent 的身份**。默认全部知识空间共用同一个 profile。

## Considered Options

### A · 一对一（一个知识空间 = 一个 profile）—— 否决

否决理由三条，第一条是硬伤：

1. **冷启动成本 ×N，直接违反 ADR-0004。** ADR-0004 §3 已定"常驻 gateway 是体验要求，不是架构偏好"——因为推理全在云端，每次冷启动都是几秒到十几秒的空窗。多 profile 意味着**每次切换空间都要换一个 gateway**，把冷启动从"一次"变成"每次切换一次"。设备是 RK3528，这不是可接受的代价。
2. **模型配置会分裂。** ADR-0003 把模型配置钉为单一事实来源（`config.yaml` + `.env`）。若每空间一个 profile，用户在空间 A 填的 API Key 在空间 B 不存在 —— 用户会认为"设置页坏了"。而模型配置是**全局偏好，不是内容**，它没有按空间切分的语义。
3. **把两套隔离绑成一套。** 内容隔离（"我想把工作和生活分开"）与能力隔离（"我要 agent 有两套记忆和技能"）是两种不同诉求，多数用户只要前者。绑死等于让所有人替少数人的需求付内存与冷启动的账。

### B · 完全无关（profile 不露面）—— 否决

纯粹主义的选择：知识空间是内容概念，profile 是内部实现，用户永不可见。

否决理由：**能力隔离是真实诉求**。用户的第 2 点原话里就带着"hermes agent 的成长"这个关注——希望 agent 有独立记忆与技能，是合理需求，不能靠"不提供入口"来消灭。而且完全不露面的代价是：多空间共用一个 agent 时，用户无从理解"为什么这个空间里的 AI 记得那个空间的事"。**不给入口，不等于消除困惑。**

### C · 解耦 + 可选绑定（采纳）

- **知识空间** = 一个内容根（文件树 + 知识点 + 关联 + 演化记录），有名字，可多个
- **profile** = agent 实例，默认只有一个（`default`），**全部知识空间共用**
- 高级设置里允许"该空间使用独立 profile"，**默认关闭**，开启时明示三条代价：内存占用、切空间时的冷启动、模型配置需要在每个 profile 里分别设置

收益：**内存预算不随空间数增长**；模型配置保持一份；绝大多数用户不会被一个自己不需要的开关打扰。

## 成长轨迹：拆成两条，不下同一张图

第 2 点的问句里混了两个主语。"成长轨迹"这个词要么指内容的长成、要么指 agent 的长成，**必须拆开**：

| 主语 | 实体 | 落点 | 属于谁 | 可视化 |
|---|---|---|---|---|
| **内容**的成长 | **演化记录** | 进化图谱页，按知识空间隔离 | 用户资产 | 是（已定，ADR-0001） |
| **agent** 的成长 | **运行记忆** + **用户技能** | 设置 & 我的 →「Agent 成长」只读区块 | 运行时私有 | 只给**存在性与规模**，不给内容 |

**为什么不能画进同一张图**：ADR-0002 §3 已经钉死「运行记忆 ≠ 知识点」。运行记忆是 agent 为自己写的私有草稿，有硬上限、会话开始时冻结快照、用户看不见也改不了。若把它的痕迹画进图谱，等于**在 UI 层推翻那条边界**——用户会以为"AI 自己记的东西也是我的知识"，而它既不可编辑也不属于用户。图谱的每一笔都必须能追溯到用户可打开的东西。

> **「成长轨迹」一词退役，不进术语表。** 界面文案不得含糊地用"成长轨迹"指代其中一边。

## 空间切换的生效条件

1. **cwd 条款措辞修订**：ADR-0002 §2 写的"agent 的 cwd 恒为知识空间根" → 修订为"恒为**当前知识空间**的根"。边界语义不变（仍然没有越权路径），只是根会随空间切换。
2. **是否需要重启 gateway —— 待验证**：若 ACP 支持 per-session cwd，切换空间只需新建会话；否则要重启。保守实现按"重启"设计。
3. **重载动作合并**：到此刻，"需要重载 agent 才生效"的动作已有三处——模型配置（ADR-0003 §3）、技能变更（ADR-0005 §3）、空间切换（本 ADR）。**三者合并为一个「重载 agent」动作**，设置页只出现一次。
4. **隔离粒度**：文件树、知识点、关联、演化记录四者都以 `spaceId` 为顶层作用域。**知识点不跨空间**——跨空间去重合并会立刻引出来源关系与图谱归属的歧义。

## Consequences

1. 侧栏「知识空间」由分组标题升格为**切换器**（形状见 DESIGN-SPEC §4.1），承担"当前在哪、能换到哪"两件事
2. 设置页新增「**知识空间**」面板：列表 / 新建 / 重命名 / 删除（危险，需确认）/ 绑定独立 profile（高级，默认关）
3. 「全部」筛选的范围随之明确：**当前空间内**，不跨空间
4. `agent/harness/` 需要维护"当前空间 → 内容根 + profile"的解析，且这是**唯一**允许改变 agent cwd 的地方
5. 术语表新增**知识空间**与 **profile** 两条，并限定"profile 是运行时概念，不是产品概念"
