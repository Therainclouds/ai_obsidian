# agent 运行时与知识空间同机，跑在设备本地

Hermes 进程**跑在知识空间所在的那台设备上**（RK3528 / ARM64 / 4GB），与知识空间文件同机。这**不是可配置项**——不提供"云端模式"，也不给用户一个开关。

Hermes 是"进程 + 云端模型"的组合：**进程本身不做推理**，它承担的是编排与 HTTP。因此"跑在哪"这件事，问的不是算力，而是**素材要不要离开设备**。

## 已核实的技术事实

| 项 | 事实 |
|---|---|
| 最低配置（官方安装页） | **1 vCPU / 512MB 内存 / 2GB 磁盘**（推荐 1GB 内存） |
| 架构支持 | ARM64 / Linux 支持；本产品的设备是 ARM64 |
| 我们是否本地推理 | **否**（D14）——全部推理在云端，进程只编排与转发 |
| 部署网络环境 | **局域网内**（2026-09-23 澄清）——设备与知识空间同网段，网络不是变量 |
| 内存实测 | **尚无**——M0 验收项，见下 |

也就是说，我们落在官方给出的**低配场景**里，而不是"跑本地模型"那个重档。

## Considered Options

- **与知识空间同机（采纳）** —— `file` 工具直接读写本地素材，零拷贝、无上传；隐私闭环。
- **Hermes 跑在云端** —— 设备零负担。放弃原因：素材必须上传；而且 agent 的 `file` 工具指向的是云端副本，**用户改本地文件后 agent 看到的是旧的**，知识空间会分裂成两份。
- **两种形态都支持（用户可选）** —— 放弃原因：会分裂两条已经定死的东西——cwd 的安全边界语义、素材的落点（本地原件还是上传副本）。收益只是"给用户一个开关"。

## Consequences

### 1 · 内存是硬预算，工具集白名单同时是内存策略

4GB 是设备上限，agent 进程要与浏览器前端共处。ADR-0002 的工具集白名单不只是安全考量——`browser` / `web` / `terminal` 正是常驻内存与子进程的主要来源。**白名单之外不再装依赖。**

### 2 · 所有推理在云端 → 「加载 / 空 / 错误」三态是常态，不是异常

每一次解析、关联、蒸馏都是一次网络往返，都可能在几秒到十几秒之间失败。所以三态不是边角补充，是主路径。

**网络边界（2026-09-23 修订）**

部署形态是**局域网设备**，本机到 agent 与知识空间**零网络跳**；唯一的网络依赖是**公网出口到云端模型**。这条修订推翻本 ADR 初稿的一处推论：

- ~~断网必须仍可用~~ → **撤销。本产品不承诺离线操作**：不设离线模式、不做离线队列。局域网内不存在"断网"这个使用场景，为它做一套降级体系是自己造需求
- 但保留它的**内核**：**失败不毁内容**。一次调用失败时——用户的消息与草稿不丢、已渲染的内容不清空、给重试出口（落到 §6.3.3 的 X1 型，而不是一个全局模式）
- 由此，初始版本说的"5W 弱网设备"是错的描述，一并撤销

§10.2 里"三态设计"那条待办仍由此从**设计缺口**升格为**运行时约束**。

### 3 · 冷启动耗时进入体验指标

agent 进程与用户在同一台设备上，"现在就想问一句"的体感 = 进程冷启动 + 首次云端往返。ADR-0002 §5 已规定复用常驻 gateway、不做 per-task overlay —— 此处再次确认：**常驻是体验要求，不是架构偏好。**

### 4 · cwd = 知识空间根，字面成立

ADR-0002 的 cwd 边界在同机形态下没有跨主机路径问题——就是一个本地目录。设置页依然不暴露此值。

### 5 · 设备是单点，数据格式必须"离得开"

知识空间就是设备上的一个文件夹。**数据模型不得引入只有我们的服务才解得开的格式**——知识点、来源关系、演化记录都必须是设备上可读的文件。备份与导出是一等功能（当前不做，但格式必须留得住）。

### 6 · 待验证项（M0 验收）

在 4GB / ARM64 上实测：**Hermes 进程常驻内存占用**与**冷启动耗时**，且必须在**浏览器前端同时开启**的场景下测。若超出预算，可退的空间是"前端与 agent 不同时重载"，不是"把 agent 挪到云端"。

## 后续修订（2026-09-23）

- **补 · 由 ADR-0008 关闭一处漏问**：本 ADR 答的是"**agent 运行时**跑在哪"，但没有回答"**谁拉起它、Harness 住在哪个进程里**"——规格书 §9.1 只列了前端栈，§9.3 却把 `acp-client.ts` / `spaces.ts` / `model-config.ts` 放在 `src/` 下，而浏览器没有进程与文件系统。ADR-0008 补上：**本地宿主**（Node 常驻）承载 Harness 与 ACP 客户端，**agent 运行时是它的子进程**，浏览器只做渲染。
- **本 ADR §6 的验收项随之改写**：实测对象由"Hermes 进程"改为"**宿主 + agent 两个进程之和**"——宿主自己也进内存预算（ADR-0008 §5）。
- **撤销规格书 §9.1.1 的一处旧句**：原文「云端 = 编排 Harness + 决策层 + 生成层 + 索引」与本 ADR 冲突——Harness 若在云端，就无法以本地路径为 cwd、无法写设备上的演化记录、无法读 `~/.hermes/config.yaml`，本 ADR 的整条论证会瓦解。该句已在 DESIGN-SPEC **v1.4** 撤销。
