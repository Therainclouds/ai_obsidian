# 模型配置以 Hermes 原生配置文件为单一事实来源

设置页的「AI 模型」面板不自己另存一份模型配置，而是**读写 Hermes 的原生配置**。Hermes 有清晰的配置职责分离：

| 配置项 | 落点 | 例子 |
|---|---|---|
| 主模型 | `config.yaml` 顶级 `model` | `model: anthropic/claude-sonnet-4` |
| 自定义端点 | `config.yaml` `custom_providers[]` | `name` / `base_url` / `api_key` / `api_mode` |
| 服务商密钥 | `.env`（UPPER_SNAKE 命名） | `ANTHROPIC_API_KEY=sk-ant-...` |
| OAuth 凭证 | `auth.json` | Nous Portal 等 |

理由是**防漂移**：Hermes 有自己的 CLI（`hermes model`、`hermes config set`），用户随时可能在终端里改。UI 若另存一份，两边必然分叉，而且分叉的方向是致命的——**agent 读到的是文件里的配置，不是 UI 以为的配置**。用户会看到"设置页写着 A，实际跑的是 B"。

写入路径有优先级：

1. **优先调 Hermes CLI**（`hermes config set <key> <value>`）—— 这是官方写入口，它自己知道该写哪个文件、写什么格式。
2. **Fallback 才直接改文件**，且必须用**保留注释的 YAML 读写**（如 `ruamel.yaml`）。不得用会丢注释和键序的普通 round-trip —— 用户手写的配置文件被 UI 一保存就面目全非，是不可接受的。

## Considered Options

- **Hermes 原生配置（采纳）** —— 单一事实来源，CLI 与 UI 改的是同一份。
- **UI 自己存一份配置**（如应用数据库 / localStorage）—— 读写自由、能加 metadata。放弃原因：必然漂移，且 UI 改了 agent 读不到，除非再写一个同步器，而同步器就是漂移的另一个来源。
- **只读不写** —— 设置页只展示当前模型、改配置一律去终端。放弃原因：本产品的用户不是开发者，要求她敲 `hermes config set` 等于把核心能力关在门外。

## Consequences

### 1 · 密钥单向：可写不可读

面板接受用户**输入**密钥，但**永不回显明文**——已保存的密钥读回来只给掩码（如 `sk-ant-••••3f2a`），"更换"是唯一的编辑入口。`.env` 明文落在设备上，不经过前端存储，不进 localStorage。

### 2 · 两个模型位，不是一个

生成层与决策层是两个独立的服务，必须分别配置：

| 位 | 谁 | 需要的字段 |
|---|---|---|
| 生成层 | Hermes 主模型 | 服务商 + 模型 + 密钥（+ base_url） |
| 决策层 | Jev 类，OpenAI 兼容端点 | base_url + 模型 + 密钥 |

决策层默认按"自定义 OpenAI 兼容端点"配置——因为 Jev 官方服务未向中国大陆开放、原版权重未开源，**自建云端跑开源复现**（Open-Jev：Qwen3.5-9B + LoRA + 决策头）是现实路径（见 §9.1.2）。面板必须能表达"这一位还没配"，而不是假设两者同源。

### 3 · 改动需要重启 agent

模型配置在 **agent 运行时**启动时读取。面板保存后必须**显式告知生效条件**，并提供一个"保存并重启"动作——不能让用户改完以为立刻生效。

### 4 · 面板必须自带连通性验证

配置模型最容易错的地方是密钥和 base_url。面板提供**测试连接**：向端点发一次最小请求，回传三态——成功（含延迟与模型可用性）、鉴权失败、模型服务不可达。设备在局域网内而推理在云端，**出网只有这一条路**（ADR-0004），这个按钮是配置流程能不能走通的关键。

### 5 · 状态语义色不动摇三色体系

连接状态需要"成功 / 需要注意 / 中性"三种表达，但设计原则是**零第四色**。解法是复用已有语义，不新增颜色：

- **成功 / 运行中** → 主色（靛即"一切在正常运转"）
- **需要注意 / 失败 / 待配置** → 点缀色（陶的既有语义就是"需要注意的"）
- **未启用 / 中性** → 墨灰

此规则升格为通用规则，写入 DESIGN-SPEC §3.4，适用于全站所有状态表达。
