## 1 · 架构确认

**agent 运行时跑在本地，大模型在云端。渲染器是一个桌面应用，不是一个网页**（v1.5 · ADR-0009）。

```
设备本地 ────────────────────────────────────────┐
  Electron 应用                                   │
    渲染进程（渲染器 · 无文件系统 / 无进程）        │
      ↕ IPC（唯一通道 · preload 白名单 · 无端口）   │
    主进程 = 本地宿主（Node）                       │
      ↕ stdio JSON-RPC（ACP）                     │
    agent 运行时 = Hermes（宿主的子进程）           │
└──────────────────────┬──────────────────────────┘
                       │ 公网 HTTPS（唯一出网路径）
                云端：决策层（判断） + 生成层（写字）
```

这条不是新的——ADR-0004 + ADR-0008 + **ADR-0009** 已经定过。写在这里是因为**接口命名要按它分区**：`host.*` 域指的是**本机那个进程**，不是云端。云端模型没有对外 API，它藏在 agent 运行时内部。

> **v1.5 变更**：渲染器由浏览器改为 Electron 应用，宿主由"独立 Node 进程"改为"**主进程**"，通道由 **localhost HTTP + SSE** 改为 **IPC**。**下文 §2 的通道选型随之整体失效，待重写**——保留原文只为对照，不要再据此实现。

## 2 · 通道选型：为什么是 stdio + IPC

依据是「通道直接走最稳定的」。

> **v1.5 修订**（ADR-0009）：渲染器形态从"浏览器"改成"桌面应用"之后，本节第二段的结论随之改变。**保留旧文只为对照**。

### 2.1 宿主 ↔ agent 运行时：`stdio`（不变）

| 候选 | 判断 |
|---|---|
| **stdio JSON-RPC（ACP）** | ✅ **采纳**。无端口、无 socket、无孤儿进程；子进程生命周期天然绑定宿主；「一个 home 一个 agent」（ADR-0002 §5）天然满足。**已实测跑通**（`docs/M0-行动清单.md` 1a） |
| TCP/IPC bridge broker | ❌ 否决。ekko-studio 用它是因为**多个 UI 客户端要共享一个 Hermes**。我们只有一个宿主、一个 agent，多一层 broker 只多一类故障：端口占用、socket 残留、鉴权面 |

> **broker 解决的是「多方共享」，我们没有这个问题。**

**v1.5 不改这一条。** 桌面壳换掉的是"渲染器 ↔ 宿主"，不是"宿主 ↔ agent"。stdio 那一段本来就在宿主内部，它跟外壳无关——这也是 ADR-0009 能只改 150 行的原因。

### 2.2 渲染器 ↔ 宿主：`IPC`（v1.5 取代 `HTTP + SSE`）

| 候选 | 判断 |
|---|---|
| **IPC（`ipcRenderer.invoke` + `webContents.send`）** | ✅ **采纳**。同一个应用内的进程间通信：**没有端口**（不会撞端口、不会被别的本机进程蹭到）、**没有网络栈**（不需要 CORS、不需要 `EventSource` 的自动重连实现）、**天生双向**、**天然有推送**。零新依赖——它在 Electron 里 |
| ~~HTTP + SSE~~ | ❌ **v1.4 采纳、v1.5 废弃**。它当时是对的：渲染器是浏览器，浏览器只能走网络。渲染器改成桌面应用后，这一层的理由整体消失——为了两个同机同应用的进程去开一个 TCP 端口，是多出来的东西 |
| WebSocket | ❌ 前提已不成立。它要解决的是"HTTP 只能单工"，而 IPC 本来就是双工的 |
| Socket.IO | ❌ 同上且更重。ekko-studio 选它是因为要同时跑 Web 终端 PTY、群聊、多 agent 并发流 |

**安全面比 HTTP 更紧，不是更松**：渲染进程跑在 `nodeIntegration: false` + `contextIsolation: true` 下，能调用的方法**只能**是 `preload.ts` 里显式列出的那些。HTTP 时代它对 `/api/*` 是"只要能发请求就能试"；IPC 时代它**连"随便发一个请求"的能力都没有**。ADR-0008 §2「宿主是知识空间唯一写入者」由此更硬。

> **ADR-0008 §6.1 那条悬置项一并关闭**：它写"唯一会推翻 HTTP/SSE 的情形是双向高频 + 中途打断生成"——**IPC 天生满足**，不用等。WebSocket 不会再出现。

## 3 · 命名规范

### 3.1 通道方法名：按**归属域**分区

> **v1.5**：路径形状由 `/api/<domain>/<resource>` 改为 `<domain>.<resource>`（IPC 不是 URL，没有斜杠）。分区原则不变。

```
<domain>.<resource>
```

| 域 | 路径前缀 | 管什么 | 对应术语 |
|---|---|---|---|
| 宿主自身 | `/api/health` | 进程存活 | —— |
| agent 控制面 | `/api/agent/*` | 本机 agent 运行时的状态、会话、对话 | agent 运行时 · 会话 |
| 知识空间 | `/api/space/*` | 建 / 改名 / 切换 / 删除 | 知识空间 |
| 素材 | `/api/material/*` | 收集器与解析器的产物、文件树 | 素材 · 文件素材 · 对话素材 |
| 知识点 | `/api/knowledge/*` | 蒸馏的产出 | 知识点 |
| 关系 | `/api/relation/*` | **两类关系分路径** | 来源关系 · 关联 |
| 演化 | `/api/evolution/*` | 演化图谱的数据源 | 演化记录 |
| 设置写链路 | `/api/settings/*` | 模型位 / 技能 / profile 的受限读写 | 模型位 · 产品技能 · 用户技能 |

**已经落地的**（与本文档一致）：

| 端点 | 状态 |
|---|---|
| `GET /api/health` | ✅ |
| `GET /api/agent/status` | ✅ |
| `POST /api/agent/chat` | ✅ |
| `GET /api/events` | ✅（全局事件流，见 §3.3） |

> **两条硬规则**
> 1. **`来源关系` 与 `关联` 不得合并成一个端点或一个计数**（CONTEXT.md：两者不是一回事）。前者走 `/api/relation/source/*`，后者走 `/api/relation/association/*`。
> 2. **`周期回顾` 没有写入端点** —— 它是视图，不落盘（ADR-0007）。

### 3.2 事件名：`<域>.<事件>`，小写点分

SSE 的 `event:` 字段一律用这个形状，域与 §3.1 的路径域一一对应：

| 事件名 | 方向 | 含义 | 状态 |
|---|---|---|---|
| `agent.stage` | 宿主 → 渲染器 | 「AI 正在做」三段阶段（读取素材 / 整合与关联 / 写知识点） | **已实现** |
| `agent.delta` | 宿主 → 渲染器 | 生成本文的流式增量 | **已实现** |
| `agent.error` | 宿主 → 渲染器 | 一次调用失败（X1…X5） | **已实现** |
| `agent.done` | 宿主 → 渲染器 | 本轮结束 | **已实现** |
| `evolution.recorded` | 宿主 → 渲染器 | 落了一条演化记录 | 类型已定，**留空** |
| `material.collected` | 宿主 → 渲染器 | 收集器入库了一批素材 | 类型已定，**留空** |
| `material.parsed` | 宿主 → 渲染器 | 解析器读完了 | 类型已定，**留空** |
| `knowledge.distilled` | 宿主 → 渲染器 | 沉淀器产出知识点 | 类型已定，**留空** |
| `relation.proposed` | 宿主 → 渲染器 | 关联器提议了一条待确认关联 | 类型已定，**留空** |

**为什么 `agent.stage` 不用过去式**：它是"正在做"，不是"做完了"。用词按事实，不按语法——完成态一律用明确的过去分词（`done` / `recorded` / `distilled`）。

### 3.3 一条流还是多条流 *（v1.5 修订）*

- **全局事件** —— 宿主主动推的（演化记录 / Hook 进度 / 素材入库），渲染器**订阅一次**。**IPC 天生有推送，不需要一条常驻连接**：v1.5 删掉了 `GET /api/events` 和它那个 15 秒 keepalive —— 那是为了"让 SSE 不断"才存在的东西，不是需求
- **对话** —— **每次调用一条请求作用域的流**：`window.host.stream('agent.chat', payload)` 只承载这一轮的 `agent.stage` / `agent.delta` / `agent.error` / `agent.done`。一次流一个通道名（`host:stream:<reqId>`），**避免多条流互相串帧**

> 分开的理由不变：对话是"我问你答"，事件是"系统自己发生的事"。混在一条流里，"哪条消息属于哪一轮"就得靠 id 猜。

### 3.4 TypeScript 命名（`shared/`）

| 种类 | 规则 | 例 |
|---|---|---|
| 领域实体 | 单数 PascalCase | `Material` · `KnowledgePoint` · `EvolutionRecord` · `SourceLink` · `Association` |
| 判别值 | 字面量联合，**不用 enum** | `MaterialKind = 'material' \| 'distilled'`（ADR-0007：只有两个取值） |
| 请求 / 响应 | `<动词><实体>Request` / `<动词><实体>Response` | `CreateMaterialRequest` · `ListKnowledgeResponse` |
| 事件载荷 | `<域><事件>Event` | `AgentStageEvent` · `EvolutionRecordedEvent` |
| 常量 | SCREAMING_SNAKE_CASE | `AGENT_STAGE_ORDER` · `SPACE_ROOT_MARKER` <!-- v1.5 删掉 HOST_PORT：没有端口了 --> |

**禁止**在类型名或字段名里出现 `CONTEXT.md` 列为 `_Avoid_` 的词（`clip` / `crystal` / `summary` / `link` …）。**代码里的字段名与用户看到的名字必须是同一个词**——这是 CONTEXT.md 那条纪律在类型层的投影。

### 3.5 文件与目录命名

```
agent/                        # 本地宿主（跑在 Electron 主进程里；顶层，不在 src/ 下）
├─ ipc.ts                     # 方法表：方法名 → 处理器。**与传输无关**
├─ services/                  # 可复用行为
│  └─ agent.service.ts
├─ acp-client.ts              # 适配器：ACP over stdio 的协议实现
├─ harness/                   # 四个 Hook 的确定性编排（唯一允许串 Hook 的地方）
├─ spaces.ts                  # 知识空间解析（唯一允许改 cwd 的地方）
├─ model-config.ts            # 读写 ~/.hermes/config.yaml + .env（ADR-0003）
└─ decide.ts                  # 决策层接口；decidedBy 随结果一起落库

electron/                     # 桌面壳：只有 boot 与桥，不放业务（v1.5 新增）
├─ main.ts                    # boot：建窗口、装 IPC、把方法表挂上去
├─ preload.cjs                # contextBridge 白名单 —— 能力面全由它决定
└─ selftest.ts                # 冒烟自检（electron . --selftest）

shared/                       # 两侧共用：领域类型 / 事件载荷 / 方法名 / 错误码
src/                          # 渲染进程（页面与样式）
```

- **v1.5 删掉的三处**：`routes/`（它原来的职责是"读 HTTP 体、拼 HTTP 响应"，IPC 下**全部消失**，只剩"方法名 → 处理器"那张映射——那就是 `ipc.ts`）、`lib/`（json / sse 原语随 HTTP 一起删）、`index.ts`（旧 boot 现在在 `electron/main.ts`）
- 目录名：**小写、单数、无缩写**
- 文件名：小写、点分**角色后缀**（`.service.ts`）
- `ipc.ts` **不得**直接 import 适配器（`acp-client.ts` 等）——只能经 service
- `preload.cjs` **必须是普通 CJS**：它跑在渲染进程的沙箱里，**不走 Node 的模块加载器**，主进程那条 type stripping 不适用。它只做转发，逻辑在上游

### 3.6 分层与依赖规则

> **方法表保持薄；只有它做"校验载荷、把失败翻成事件"；service 承载可复用行为；只有 boot（`electron/main.ts`）可以组合具体模块与适配器。跨域代码归 `harness`。**
>
> 一个域模块**不得**因为"今天用到了它"就吸收共享能力。

借自 ekko-studio 的原文（`packages/server/src/modules` 的依赖规则）：

> *"Routes stay thin, controllers own HTTP concerns, services own reusable behavior, and only `packages/server/src/bootstrap` may compose concrete modules and adapters. Cross-agent code belongs to Studio; an agent module must not absorb a shared product surface merely because it uses that agent today."*

映射到我们这里 **（v1.5 改：`route` 层随 HTTP 消失，boot 移到 `electron/`）**：

| 层 | 文件 | 允许 | 禁止 |
|---|---|---|---|
| **boot** | `electron/main.ts` | 组合模块与适配器；建窗口；注册方法表；收尾 | 写业务判断 |
| **方法表** | `agent/ipc.ts` | 方法名 → 处理器；校验载荷；把失败翻成事件 | 直接调 `acp-client`；写业务逻辑 |
| **service** | `agent/services/*.service.ts` | 可复用行为、数据读写、调适配器 | 碰 IPC / 窗口对象 |
| **adaptor** | `agent/acp-client.ts` · `spaces.ts` · `model-config.ts` | 只做"与外部世界说话" | 承载领域判断 |
| **harness** | `agent/harness/` | 四个 Hook 的确定性编排 | 被方法表直接调用（必经 service） |

> **v1.5 的净效果**：层数没变（boot / 表 / 服务 / 适配器 / 编排），但**"HTTP 关注点"这一整类职责消失了**——没有请求体要读、没有响应要拼、没有方法不匹配要防。`route` 与 `lib` 两层随之删除，净减约 145 行。

>

> #### 更正（2026-10-03 晚 · S3 期间实测推翻了原来的理由）
>

> 所以现在的状态是：**缺口还在，但挡住它的不是环境，是没人去做那件事**（提示词怎么给事实、
> 结构化输出怎么解析、失败怎么落）。这条更正留着，是因为**一个错的理由比没有理由更坏** ——
> 它会让人以为"等换了环境就能做"，而实际上现在就能做。

### 怎么验收一期

三步，缺一不可：

1. **`npm run selftest:mock`** —— 功能对不对（读的口径 + 写的回路 + 派生数重算）
2. **`npm run shots`** —— 长得对不对。逐页截图到 `design/app-shots/`
3. **`npm run start`**（不带 `--mock`）—— 空态对不对。**空态是另一套界面**，夹具跑得通不代表它是空的时侯也成立

> **截图分两处，别混**：`design/prototype/shots/` 是**基准**（原型长这样），
> `design/app-shots/` 是**实现**（我们的应用长这样）。混在一起"基准"这个词就失效了 ——
> 改实现时不小心覆盖了基准，就再也没法比。
>
> 截图时**锁亮色**：应用默认跟随系统偏好，而这台开发机是暗色；不锁的话，
> 我们拍的（暗色）与无头浏览器拍的原型（默认亮色）根本没法比。

### 实现分期（4 期 · **每期一个页面**）

**分期原则：按页面切，不按层切。** 一期结束时，**那一个页面是真的**——数据经真实接口从宿主来，不是渲染器里塞的假数据。这样每期都有可验收的东西，而且**下一期不会再回头改上一期的页面**。

| 期 | 覆盖 | 方法数 | 验收（"真的"的判据） |
|---|---|---|---|
| **S1** ✅ | **文件管理页** —— 存储层 + 夹具 + `space` · `folder` · `material` · `knowledge` · `association` · `evolution` · `stats` | 24 | 树、列表、知识点视图、关联图全部来自宿主；**`src/features/files/demo.ts` 已删**。**已完成（2026-10-03）** |
| **S2** ✅ | **知识总结页** —— `stats` · `review` | 1 | 四张统计卡与热度柱是**算出来的**，周期回顾是**现生成**的；**`src/features/summary/demo.ts` 已删**。**已完成（2026-10-03）**；`review` 的生成层那一半是缺口（见上） |
| **S3** ◐ | **聊天页** —— `conversation.*`（4）+ 挂上已实现的 `agent.chat` | 4 | 对话历史**真的在写、在存、在显示**（消息由宿主写，见上）。**两处留给设计**：对话历史左栏的展开入口（D39 定了"默认收起的左栏"，但**没定怎么展开**，而目标机是触控、没有 hover，"收起态与原型逐像素一致"与"用户能发现入口"无法同时成立）；「依据」卡片（D41 定了要它，但**原型里没有它的样式**——原型占位回复写着"正式版会给出"）。**另：落盘布局未定**（见下） |
| **S4** | **设置页** —— `model.*`（3）· `skill.*`（5）· `agent.reload` / `agent.arrange` · **全局事件生产端** | 11 | 模型配置能存能测；「AI 整理」真的会跑解析器 + 关联器并回流事件 |
| **S5**（新登记） | **落盘** —— `agent/store/fs.ts` | —— | "**重启后还在**"。**它被一条未定项挡住**：D38 说对话历史"由产品自己存"，ADR-0006 说四类内容"以 `spaceId` 为顶层作用域"，但**没有任何一处文档说磁盘上长什么样**。这是 S3 撞出来的，详见下 |

> ### ⚠ S3 撞出来的未定项：知识空间的**磁盘布局**
>
> 今天整条存储层都是**内存**的（夹具 + 内存 store），所以"重启后没有"不是缺陷、
> 而是**全库一致的现状**。加落盘才会引出真正的决定：
>
> - 产品自己的数据（知识点 / 关联 / 演化记录 / 对话历史 / 索引）**落在哪** ——
>   内容根里面（`.space/` 之类的隐藏目录）还是外面（应用数据目录）？
> - 素材的元数据（`mimeType` / `sizeBytes` / `tags` / `favorite`）是**另存一份**，
>   还是**写在素材文件的头里**？（后者让用户在 Finder 里直接编辑也带得走，前者不会）
> - 格式与原子性（一坨 JSON / 一行一条 JSONL / SQLite）
>
> **为什么要先定**：它影响**每一个将来要持久化的实体**，不是只有对话历史；
> 目标机是**专用设备**，备份与迁移都挂在它上面；而且设置页那个空着的
> 「**存储与同步**」模块直接吃这条决定。**按本项目纪律：先改文档再改代码**，不猜。

> **为什么按页面切而不是按层切**：按层切（先全做"存储层"、再全做"服务层"）在每一层的边界处都验收不了任何用户可见的东西 —— 而本项目反复吃过这个亏（`§9.4` 那张里程碑表就是横切的，M0–M4 刷完 5 个页面，产出**全是占位**）。
> 按页面切还有个附带好处：**每期都会逼出一个真实问题**（S1 逼出"文件夹能不能嵌套"、S2 逼出"统计口径"），而不是等到最后统一爆炸。

### 夹具（Mock）数据的放法与开关

**现在假数据散在渲染器里**（`src/features/files/demo.ts`、`src/features/summary/demo.ts`），页面**绕过接口直接 import**。这条路要拆掉，理由是它会掩盖接口问题：**页面显示的"对"，无法证明接口是对的**。

**改成宿主侧一处夹具**：

```
agent/
├─ mock/
│  └─ seed.ts        # ★ 唯一一处夹具数据，类型由 shared/types.ts 约束
└─ store/
   └─ memory.ts      # 内存存储：夹具预填它，方法表读它
```

- **开关**：`--mock`（`npm run app:mock` / `npm run start:mock`）。**不带它 = 空态**——这本身也是一个要看的界面（`§6.3` 的 E1 首次空态）
- **必须可见**：`HealthPayload` 加 `mock: boolean`，界面据此标明"这段数据是示例"。**假数据不可见就会开始被当成设计**——本项目已经吃过一次（那批原型示例数据差点被当成真实结构）
- **将来怎么退场**：夹具**不是临时脚手架**，它有两个正式用途 —— ① 新装设备的**示例知识空间** ② 端到端测试的**固定输入**。所以它不会被删，只会从"默认数据源"退成"一个可选数据源"
- **`store/memory.ts` 将来会被 `store/fs.ts` 取代**（真实落盘）。**方法表不感知这件事**——这正是 `agent/ipc.ts` 与传输/存储都解耦的价值

**夹具要填哪些字段**：不需要单独列清单——**夹具的类型就是 `shared/types.ts`，编译器会逐个字段要求**。凡是那个文件里没有 `?` 的字段都必须给值，这就是"哪些字段需要示例值"的答案，而且它**不会随文档过时**。

## 5 · 与 ekko-studio 的差异（有意为之）

| | ekko-studio | 我们 | 为什么 |
|---|---|---|---|
| agent 进程接入 | Bridge broker（`tcp://127.0.0.1:18765` / `ipc://`） | **ACP over stdio** | 他们是多客户端共享一个 Hermes；我们一个宿主一个 agent，broker 是净增故障面 |
| 实时流 | Socket.IO `/chat-run` | **IPC**（v1.5 前是 HTTP + SSE） | 我们只需**单向流 + 一条请求作用域的流**（§2.2）；双工由 IPC 自带，不必叠一层 WebSocket |
| 形态 | Electron 桌面 + Web 控制台 + CLI + Docker | **Electron 桌面，主进程即本地宿主** | 与他们**同壳而异构**：v1.4 曾以"Electron 常驻 150MB+"否决它，那条理由**对浏览器同样成立**——见 ADR-0009。我们借它省掉的是**浏览器（独立产品）与 localhost HTTP 一整层**，而不是内存 |
| 多租户 | 有鉴权、JWT、entitlement | **无鉴权** | 单用户单机（D14 / ADR-0004） |
| **抄了什么** | 分层依赖规则（§3.6）· 路径按域分区 · 模块目录用连字符小写 · 迁移时旧名保留为别名 | | |

> **迁移兼容策略也一并采纳**：将来若改名，**旧路径 / 旧事件名保留为别名**，不做静默破坏。他们为此专门维护了一份 API migration contract。
