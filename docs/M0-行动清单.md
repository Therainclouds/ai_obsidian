**③ ⚠ 一条之前没人问过的硬前提：设备上必须有 X11 显示服务器。**

这是**今天新出现的门槛**——ADR-0004 / 0008 / 0009 一直在算内存，**没有任何一条问过"设备有没有图形栈"**。而它比内存更容易一票否决：

- Electron **不是** framebuffer 程序。X11 那整族库都是硬依赖
- 若设备是**无头**（没装 X/Wayland），Electron **直接不成立**（挂 `xvfb` 能启动，但我们要给人看，没有意义）
- Wayland 机器要靠 **XWayland**

**退路（诚实说）**：若设备确无图形栈，则 **ADR-0008 的"宿主 + 局域网浏览器"反而是唯一活得下来的方案**（从另一台机器开浏览器），代价是宿主得监听非 localhost、安全面要重估。**这是旧方案唯一比新方案强的情形**，也是 ADR-0009 的残余风险——**必须尽早核，不能等。**

### 3.3 怎么核（在设备上跑，几分钟）

```sh

ldd --version | head -1                    # glibc ≥ 2.25
echo "$XDG_SESSION_TYPE"; ls /tmp/.X11-unix 2>/dev/null   # 有没有显示服务器
ldconfig -p | grep -E 'libgtk-3\.so\.0|libnss3\.so|libX11\.so\.6'
# 最直接：把 electron 目录拷过去，一次看到全部缺哪个
ldd ./electron | grep 'not found'
```

## 5 · 关于方案本身的一点判断

**够硬的部分**：32 条决策记录（D1–D32）· 8 条 ADR · 26 个术语 + 三套自动校验器 · 一条不变量贯穿（"产出为空的是日志不是演化"）。
这个密度在个人项目里不常见，最大的收益是**每次定案都留了"为什么否决另外两条路"**——ADR-0008 能一次写完五个候选，靠的就是前面五条 ADR 已经把边界钉死了。
