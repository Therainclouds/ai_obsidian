## 四、技术选型评审：规格书缺了一个"宿主层"

§9.1 技术栈表罗列的是：

> React + Vite + TypeScript · Tailwind · shadcn/ui · Magic UI · 运行时 Hermes Agent ·（状态：**Zustand 或 TanStack Query，待后端形态确定**）

但 §9.3 的目录结构把下面这些放在 `src/agent/` 下：

```9:9:design/DESIGN-SPEC.md
│  ├─ acp-client.ts       # ACP over stdio：会话生命周期、流式消息
│  ├─ harness/            # 四个 Hook 的确定性编排（收集/解析/关联/蒸馏）
│  ├─ spaces.ts           # 知识空间 → 内容根 + profile 解析
│  ├─ model-config.ts     # 读写 ~/.hermes/config.yaml + .env（ADR-0003）
```

这些要做的事，**浏览器页面一件都做不到**：

- `spawn` 一个 `hermes acp` 子进程并持有 stdio
- 读写知识空间目录（Harness 写演化记录与知识点文件）
- 读写 `~/.hermes/` 下的 `config.yaml` / `.env`
- 建立并维护索引

→ **§9.1 技术栈少了一层：承载 Harness 的本地宿主。** 这一层不定，M0 骨架无从搭起。这也正是 §9.1 状态行那句"待后端形态确定"悬着的原因。

## 五、顺带发现一处架构口径冲突（需定案）

§9.1.1 的架构形态原文：

```1526:1526:design/DESIGN-SPEC.md
**架构形态**：客户端 = **瘦渲染器**（渲染 + 本地缓存 + 交互）；云端 = 编排 Harness + 决策层 + 生成层 + 索引。
```

**把「编排 Harness」放进了云端。** 这与另外四处定案直接冲突：

| 出处 | 原文 |
|---|---|
| ADR-0004 §3 | 常驻 gateway 在**设备本地**；"agent 进程要与浏览器前端共处" |
| ADR-0002 §5 | Harness 复用同一个 home 与**常驻 gateway** |
| §9.6 边界 1 | cwd 恒为**当前知识空间的根**（一个本地目录） |
| §10.2 C | 后端形态含 Harness + 决策层接口 + **Hermes 运行时** |

若 Harness 真在云端，则它无法以本地路径为 cwd、无法写设备上的演化记录、无法读 `~/.hermes/config.yaml`——ADR-0004 整条（含"素材不离开设备"的理由）随之瓦解。

**判断**：这是 §9.1.1 在 v1.0（D14 时代）写下的旧句，ADR-0002/0004 定案后没有回头修订。四处定案对一处旧句，**该改的是 §9.1.1**，建议改成：

> 客户端 = 瘦渲染器（渲染 + 本地缓存 + 交互）；**设备本地 = 渲染器 + Harness + agent 运行时**；云端 = 决策层 + 生成层 + 索引（**只吃算力，不吃编排**）。
